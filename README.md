# REDBOOL

앉은 자세의 카메라 동작으로 플레이하는 대전 게임입니다. 스토리 모드와 같은 결투장을 두 노트북에서 보는 LAN **PvP 대전**을 지원합니다.

현재 개발 단계는 **v36.3 X자 인식·반응 개선 시험**입니다. 새 게임은 검증된 Heavy 보조 모델을 명시적으로 요청하며, 카메라 처리 여유와 신선도 조건을 통과할 때만 사용합니다. 기본 인식으로 X자가 성공하면 불필요한 추가 추정을 중단합니다. 기존 캐릭터·스토리·PvP와 화면 통신 규약33을 유지합니다. Python 소스 개발 실행은 기본 OFF입니다.

v36.2의 직접 캐릭터 선택·준비 안내를 유지합니다. PvP 인물 선택을 각자의 방향키·마우스와 **선택 완료** 버튼으로 바꾸며, 몸동작이나 시간 경과로 인물을 확정하지 않습니다. v36.1의 저사양 대응, 개인 보정, 스토리와 전투 입력 만료 규칙을 유지합니다. 기본 시작 화면에서는 빠른 대전·버전·기록 관리 표시를 숨기고, 진단 ZIP은 **메인 메뉴 → 설정 → 진단 기록 저장**에서 만듭니다. 배포 빌드는 `--release`로 만들며 Development Build 표시가 없습니다.

Unity Editor는 **6000.4.5f1**이며, 확인한 팀 게임 원본은 `feature/unity`의 `9c656fa`, PvP 원본은 `feature/pvp-lobby-tutorial`의 `2c4e091`입니다. 현재 KO 클립은 두 원격 브랜치와 같습니다. 예전 과장된 KO를 되돌린 후속 팀 수정을 유지하며, 별도로 푸시되지 않은 팀원 로컬 작업은 포함되지 않습니다. 최신 커밋의 공통 KO/시간 종료 글자 연출을 별도 PvP 결과판에도 연결합니다. 승패·시간·피격 판정이나 재대전 수련 유지 규칙은 바꾸지 않습니다.

진단025에서는 보정이 완료됐지만 30fps 취득에 비해 처리 속도가 약 11fps여서 인식 준비 이력이 반복 초기화됐습니다. v36.1은 150ms가 지난 출력을 계속 즉시 중립으로 만들고 대기 공격도 폐기합니다. 내부 이력만 최대 220ms 안에서 보관하고, 같은 사람·촬영 세션의 다음 관측이 촬영 간격 100ms 이하·현재 입력 나이 120ms 이하·양팔 유효일 때만 이어갑니다. 실제 공백·오래된 관측·사람 변경·C 재보정은 초기화합니다. 저장 기록의 준비 상태는 0→70프레임, 1→27프레임으로 개선됐고 정상 기록 18,557프레임·79개 공격은 그대로였습니다. 이 비교는 실제 저사양 PC의 FPS나 게임 완주를 보장하지 않습니다.

- PvP는 대기실 → 각자 보정 → 12명 중 인물 선택 → 개인 동작 수련 → 대전 순서입니다. 인물별 외형과 필살기가 적용됩니다.
- 선택 중 연결이 끊기면 선택을 보류합니다. 확인 요청은 해당 선택 회차·선택값에만 적용하며, 이전 확인으로 다른 인물을 자동 확정하지 않습니다.
- 기존 입력 만료·중복 방지, 포트 충돌 안내·재시도, 양쪽 최신 신호를 확인한 뒤 재개하는 규칙을 유지합니다.
- 전투에서는 필요한 피격·기 부족 안내만 짧게 표시하고, 보정 후 카메라를 줄입니다. 새 PvP 수련은 상세 카드와 작은 내 미리보기를 함께 보여줍니다.
- 스토리 저장 보호, 공통 Esc·설정, 최신 수련/지도 BGM, 별도 운영자 시험 기능을 유지합니다.
- 카메라와 게임이 함께 느리거나, 카메라 준비 중에도 게임 자체가 지속해서 20fps 미만이면 안정된 5초 구간 2회 뒤 3D만 720p 범위로 줄입니다. 로딩·장면 전환·백그라운드·메뉴 구간은 제외하며 모델·입력 해상도·인식 기준은 바꾸지 않습니다. 화면 아래로 팔이 잘린 경우에는 거리 조정 안내를 먼저 보여줍니다.
- **두 노트북 모두 같은 v36.3 시험본을 사용하세요.** 직접 인물 선택 요청을 추가한 화면 통신 규약은 **33**입니다. 규약 32 이하인 기존 배포본과 혼용하지 않습니다. 카메라 입력 규약과 LAN 포트는 그대로이며, Wi-Fi마다 다시 빌드할 필요는 없습니다.
- 원본 영상 없이 관절·인식·통신 진단을 저장합니다. 기록은 자동 삭제하지 않습니다.

인식 수정의 검증 결과는 [Python 브랜치의 v36.3 안내](https://github.com/Capstone-Design-2026/motion-fighter-ai/blob/codex/tutorial-personal-pvp-20261112/docs/x-latency-release-20261116.txt)를 확인하세요. 유지하는 v36.2 게임 기능은 [`Tools/Developer/V36_2_TEST_RELEASE.txt`](Tools/Developer/V36_2_TEST_RELEASE.txt)에 정리했습니다. 이전 저사양 수정 근거는 [`Tools/Developer/V36_1_CONNECTION.txt`](Tools/Developer/V36_1_CONNECTION.txt)를 참고하세요.

수련은 같은 촬영 프레임의 짧은 만료 알림만 제한적으로 기다립니다. 공백 중에는 성공 횟수나 복귀 시간을 늘리지 않으며, 유효한 관측 구간만 복귀 시간으로 누적합니다. 실제 공백·다른 사람·C 재보정·단계 변경에는 이력을 초기화합니다. PvP에서도 같은 프레임의 만료 알림이 기존의 짧은 참가자 연결 유예를 지워 버리던 부분을 보완했으며, 유예를 연장하거나 만료된 전투 입력을 실행하지 않습니다.

v34.3는 현재 게임의 입력 포트가 이전 REDBOOL·Unity Play에 점유됐으면 카메라 실행을 보류하고 안내합니다. 이전 실행을 닫으면 자동 재연결하며, 정상적인 스토리 씬 전환에서는 기존 카메라와 보정을 유지합니다. PvP 방장은 두 입력 포트를 모두 확보해야 시작하고 참가자는 기존 원격 호스트 경로를 유지합니다. 다른 프로세스는 종료하지 않습니다.

Windows 카메라는 시작 시 실제 속도를 측정하고 느린 YUY2 입력만 같은 장치의 MJPG와 비교합니다. 개선이 확인되지 않으면 복원하며 노출·게인은 바꾸지 않습니다. 정지 자세 보정의 관측 간격만 350ms까지 허용하고 12개 표본·최신 120ms·자세·공간 안정성 조건 및 전투 판정은 유지합니다. 낮은 카메라 입력 속도와 모델 처리 지연을 따로 안내합니다. 실제 장치의 FPS 개선은 현장 재검증이 필요합니다.

v34.2의 부하 대응과 공통 Esc 메뉴를 유지합니다. 미리보기는 최대 15fps, 부하 시 8fps이며 접으면 표시 작업을 멈춥니다. 고해상도 3D 렌더링은 최대 1920×1200, 지속적인 인식 처리 지연 시 최대 1280×720으로 줄이고 UI 크기는 유지합니다. 기본 보정은 Lite만, 보정 후에는 여유 있는 PC에서 Full 보조 모델도 사용합니다. 속도 우선 모드에서는 가려진 X자에 불리할 수 있습니다. Esc 메뉴를 열어도 게임은 계속됩니다. 당시 화면 통신 규약은 30이었으며 v35는 31입니다.

v34.1은 Windows 스토리 실측을 바탕으로 첫 공격용 보정 메시를 기존 전투 준비 단계에서 미리 렌더링하고, 관절 기록의 카메라 획득 번호와 운영체제 간 재생 비교를 보완합니다. 인식 모델·기준·개인 보정·공격 판정은 변경하지 않습니다. 실제 첫 타격 프레임 개선폭은 Windows에서 다음 플레이로 확인해야 합니다. 화면 통신 규약은 v34와 같은 30입니다.

v34는 팀의 Unity 변경 `85ea2de`까지 통합하고, 원본 영상 없이 인식 관절 좌표와 처리 순서를 압축 기록합니다. v33.1의 Windows 소켓 소유권 수정과 기존 인식·개인 보정은 유지합니다. 새 공격용 메시의 표시를 두 화면에서 맞추기 위해 화면 통신 규약은 **30**으로 올라갔으므로 PvP 양쪽 모두 v34를 사용하세요. 별도 게임이나 Unity Editor Play를 함께 실행해 같은 포트를 점유하지 않도록 합니다.

## 게임 실행

빌드된 패키지에서 **Mac은 `REDBOOL.app`, Windows는 `REDBOOL.exe` 하나를 실행**합니다. Unity Editor나 Python 설치, 별도 카메라 명령어는 필요 없습니다. Windows는 실행 파일 옆의 지원 폴더도 함께 유지해야 합니다.

1. 스토리·결투·수련에 들어가면 카메라가 켜지고 **내 동작** 패널이 나타납니다. 최초 카메라 권한 안내를 허용합니다.
2. 양손과 팔꿈치가 화면에 보이도록 앉아서 **보정 버튼 또는 `C`**를 누릅니다. 같은 사람은 장면마다 다시 보정하지 않습니다. 사람이 바뀌면 `C`로 재보정합니다.
3. **접기**는 미리보기 표시만 쉬게 합니다. 동작 인식은 계속됩니다. 연결 문제가 생기면 **다시 연결**을 누릅니다.
4. 메인 메뉴로 돌아가거나 게임을 종료하면 게임이 시작한 카메라도 종료됩니다.

동작은 왼손 펀치→잽, 오른손 펀치→스트레이트, 왼손 레이즈→하이킥, 오른손 레이즈→로우킥, 양손 블락, 좌우 상체 기울이기→이동, 충전 후 X자→선택한 캐릭터의 필살기입니다(스토리 주인공은 파운장). 블락은 실제 유지하는 동안 적용하고, 팔을 풀면 해제합니다.

**필살기 게이지는 일반 공격이 블락에 막히지 않고 적중할 때 찹니다.** 맞기·막기·빗나감·필살기 자체의 적중은 충전하지 않습니다. 5회 적중하면 준비되며, 게이지는 막대로 표시합니다. 이 규칙은 이번 게임 콘텐츠 통합에서도 유지합니다.

## 두 노트북으로 PvP

두 노트북을 같은 LAN에 연결하고 각각 게임을 실행합니다. 방장은 **PvP 대전 → 방 만들기** 후 대기실의 **상대가 입력할 주소 → 복사**로 IPv4를 상대에게 전달합니다. 상대는 주소 입력 후 **대전 참가**를 선택합니다. **방 찾기**는 별도의 자동 검색이며 주소를 채울 뿐 자동으로 참가하지 않습니다. 주소가 3개를 넘으면 **다른 주소**로 넘겨 모두 확인할 수 있습니다.

대기실 주소는 5초마다 갱신되며 **새로고침**으로 다시 확인할 수 있습니다. 여러 주소가 있으면 상대와 함께 연결한 Wi-Fi·유선·모바일 핫스팟의 주소를 선택합니다. 인터넷 전환용 CLAT 주소(예: `192.0.0.2`), loopback 및 명백한 가상 머신 전용 주소는 공유 대상으로 표시하지 않습니다. 사용할 IPv4가 없거나 방 포트가 열리지 않았을 때는 안내를 표시합니다. 주소가 보이더라도 공유기의 기기 간 통신 제한이나 방화벽 때문에 접속되지 않을 수 있습니다. 자세한 변경 범위는 [`Tools/Developer/V36_1_CONNECTION.txt`](Tools/Developer/V36_1_CONNECTION.txt)에 있습니다.

각 노트북은 자기 카메라를 처리합니다. 보정 후 방향키·마우스로 인물을 고르고 **선택 완료** 또는 Enter로 확정합니다. 확정 취소는 **다시 고르기** 또는 Backspace입니다. 몸동작으로 인물을 바꾸거나 확정하지 않습니다. 양쪽이 선택과 수련을 마치면 전투가 시작됩니다. 인물 선택 동작은 개인 보정 학습에 포함하지 않습니다. 호스트가 전투 결과를 결정하고 상대 화면으로 상태를 보냅니다. 인터넷 서버는 필요 없으며, 게스트가 호스트에 닿을 수 있어야 합니다. Windows 방화벽 안내가 나타나면 사용하는 로컬 네트워크에서 게임 통신을 허용하세요.

| 통신 | 포트 |
|---|---|
| 1P 카메라 입력 | 호스트 UDP 5065 |
| 2P 카메라 입력 | 호스트 UDP 5066 |
| 두 화면 상태·방 찾기 | 호스트 UDP 5067 |
| 내 카메라 미리보기·보정 버튼 | 각 PC 내부의 임시 loopback HTTP 포트 |

미리보기 영상은 상대 PC로 전송하지 않습니다. 현재 화면 통신 규약은 **33**이며, v36.3는 게임/패키지 버전입니다. 이전 규약의 게임은 같은 방에 연결하지 않습니다.

## 개발 및 패키징

- Unity **6000.4.5f1**을 사용합니다. Mac 개발과 Windows x64 데모를 지원합니다. 현재 Mac 카메라 실행 파일은 Apple Silicon용입니다.
- Editor에서는 기존 수동 Python 개발 흐름을 유지합니다. 통합 카메라는 실행 파일을 동봉한 실제 플레이어에서 작동합니다.
- Unity 빌드는 `RedboolLocalDemoBuild.Run`, 카메라는 Python 브랜치의 `scripts/build_camera_backend.py`, 최종 조립은 [`Tools/Developer/assemble_game.py`](Tools/Developer/assemble_game.py)를 사용합니다.
- Windows 카메라는 Windows에서 빌드해야 합니다. [Windows 카메라 빌드 작업](https://github.com/Capstone-Design-2026/motion-fighter-ai/actions/workflows/camera-backend-windows.yml)의 산출물은 **카메라 백엔드**이며 전체 게임 패키지는 아닙니다.
- 자동 Unity 검사·빌드에는 `UNITY_MCP_DISABLE=1`을 지정합니다. 관련 개발 플러그인의 DLL 자동 갱신이 검사 중 재컴파일을 일으키는 것을 방지합니다. 배포 게임의 통신 기능을 끄는 설정은 아닙니다.

자세한 조립 명령, 저장 위치, 카메라 없는 실행 검사는 [`Tools/Developer/V34_PACKAGING.txt`](Tools/Developer/V34_PACKAGING.txt)에 있습니다. 완성된 앱을 다시 만드는 과정이며, 사용자가 게임을 클릭할 때 Unity 빌드가 실행되는 구조는 아닙니다.

## 기록과 확인 범위

통합 패키지는 **원본 영상 없이 처리한 관절 좌표를 압축 저장**합니다. Lite 주 인식과 사용된 Full·Heavy 보조 인식의 추정 좌표·신뢰도, 처리 시각·순서, 보정과 공격 이벤트를 함께 남깁니다. 별도 작업 스레드에서 압축하며, 카메라 실행당 관절 기록은 최대 128MiB입니다. 제한·저장 실패·빠진 구간은 명시하고 게임 처리는 계속합니다. 프레임을 일부러 건너뛰어 기록하지는 않습니다.

테스트 후 **메인 메뉴 → 설정**에서 **기록 마무리 중…**이 끝나면 **진단 기록 저장**을 누르세요. 최근 3개 카메라 실행과 게임 로그가 담긴 ZIP 폴더가 열립니다. 완전히 닫힌 압축 파일만 크기·해시를 확인해 통째로 포함하고, 아직 쓰는 파일이나 손상·누락 파일은 `export_report.json`에 이유를 남깁니다. `landmarks.index.json`의 완전성·누락 정보를 확인한 뒤 재생합니다. 원본 파일은 삭제하거나 변경하지 않습니다. PvP 진단에는 양쪽 PC의 ZIP이 필요합니다.

관절 좌표는 모델의 추정값입니다. 원본 영상과 사용자의 의도 라벨이 없으므로 모든 실제 동작의 정답을 확정할 수는 없지만, 인식기가 어떤 좌표를 받고 왜 공격을 내거나 거부했는지는 훨씬 정확히 재현할 수 있습니다.

미리보기는 320×240, 최대 15fps이며 부하 시 8fps로 낮추고 인식은 기존 처리 속도로 이어갑니다. 저장 영상 비교에서는 미리보기 유무 모두 약 30fps를 유지했지만, 이 결과가 실제 Windows 카메라나 두 PC의 전체 게임 프레임을 보장하지는 않습니다.

기존 v32 동작을 유지하는 회귀 검사, 여러 사람의 수련 기록 재생, 실제 Unity 접촉·가드·필살기 검사와 동봉 모델 실행 검사를 사용합니다. 손목이 화면 밖으로 나간 기록은 임계값을 낮춰 해결하지 않고, 카메라 패널에서 구체적인 자세·구도 안내를 제공합니다. 일반화된 인식률은 별도의 실제 사용자 검증이 필요합니다.
