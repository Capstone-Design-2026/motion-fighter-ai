REDBOOL v36.2 — 직접 캐릭터 선택·준비 안내·제한적 펀치 보완

기준과 범위
Unity 6000.4.5f1. 검토한 팀 게임 원본 feature/unity 9c656fa,
PvP 원본 feature/pvp-lobby-tutorial 2c4e091. 최신 KO 14개는 현재 파일과 동일.
기존 개인 보정, 스토리 진행, PvP 전투 규칙과 입력 만료를 유지한다.
예전 과장된 KO를 되돌린 팀의 후속 결정을 임의로 취소하지 않는다.

실제 변경
- PvP 인물은 각 노트북의 방향키/마우스로 선택하고 선택 완료/Enter로 확정.
  다시 고르기/Backspace로 해제한다. 몸동작/시간 경과로 자동 확정하지 않는다.
  선택 중에는 마우스를 잡으려고 손을 내려도 조작할 수 있다.
  수련 시작은 양쪽 카메라가 다시 유효하고 선택이 확정된 뒤에만 허용한다.
- 게스트는 자기 2P 선택만 요청한다. 호스트가 연결 세션, 회차, 선택 세대와
  현재 선택의 수정 번호를 확인한다. 중복/오래된 확인으로 다른 인물을 확정하지 않는다.
- 게이지 아래에 보정 시작/보정 중/완료를 표시한다. 100% 보정과 현재 입력
  준비를 구분하며, 오래된 입력·관절 가림·화면 이탈을 준비 완료로 표시하지 않는다.
- 공통 수련/게이지의 파운장 준비 표현을 필살기로 통일. 고유 기술명은 유지한다.
- 최신 CombatAnnouncementStyle의 큰 KO/시간 종료 글자 연출을 별도 PvP 결과판에도 적용한다.
  같은 결과의 장식은 재생성하지 않으며, 승패/시간/재대전/수련 유지 정책은 그대로다.
- 기본 메뉴의 빠른 대전/버전/기록 관리를 숨긴다. 운영자 설정으로 시험 도구는
  다시 표시할 수 있다. 일반 배포에서는 Development Build 표시를 빼도록 release 빌드한다.
- PvP 진행 중 반복 조작 설명을 제거한다. 연결/준비/수련 대기 이유는 유지한다.
- 진단 ZIP 저장은 메인 메뉴 → 설정으로 이동한다. 원본 영상은 여전히 저장하지 않는다.

인식 근거와 한계
Python v36.2의 새 경로는 이미 시작된 펀치 후보 중 반대손 가드, 큰 수평 이동,
보정 대비 팔꿈치 개방을 서로 다른 두 관측에서 확인할 때만 완료를 허용한다.
팔을 뻗은 정지 자세에서 새 공격을 시작하거나 재장전하지 않는다.
150ms 출력 만료, 최신 관측120ms, 촬영 간격100ms, 내부 이력220ms 경계를 유지한다.
8개 기록47,826프레임: 기존217이벤트 보존,446 잽 수련 구간1이벤트 추가.
추가 뒤의 이벤트 순번만 증가하고 기존 동작/프레임/시점/근거는 동일하다.
다른7기록은 제어상태도 동일하며 모든 보정anchor/개인profile을 보존한다.
원본 영상 정답이 없어 전체 인식률이나 모든 펀치 누락 해결을 뜻하지 않는다.
584는 실제 전투 중24.5%프레임에서 팔 관절 이탈/가림이 있었다. 위로 크게 움직인
레이즈 기록을 일괄 펀치로 바꾸지 않는다. 모델 파일이나 기본 학습을 새로 바꾸지 않았다.

팀원 개발 빌드
Unity와 Python 브랜치를 별도 폴더에 유지한다.
Unity: codex/pvp-dual-screen-20261112 / PR14
Python: codex/tutorial-personal-pvp-20261112 / PR12
각자의 수정이 없을 때 git fetch origin 후 해당 브랜치를 git pull --ff-only 한다.
Unity Tools/Developer/build_local.py --release는 배포용 Unity 플레이어를 만든다.
통합 카메라는 Python의 scripts/build_camera_backend.py로 각 OS에서 빌드하고
Tools/Developer/assemble_game.py로 Unity 플레이어와 조립한다.
Windows 카메라는 같은 Python 커밋의 Windows camera backend CI 결과를 쓸 수 있다.
카메라 산출물만 받는 것은 완성 게임을 받는 것과 다르다.
일반 테스터는 완성 ZIP 전체만 풀고 REDBOOL.app/REDBOOL.exe를 실행한다.

PvP와 Wi-Fi
화면 통신 규약33. 양쪽 모두v36.2를 사용한다. v36.1/규약32와 혼용하지 않는다.
Wi-Fi마다 재빌드하지 않는다. 같은 통신 가능한 LAN에서 방을 만든 화면의 IP를
상대에게 전달하면 된다. 공유기 격리/방화벽은 IP 표시만으로 해결되지 않는다.
카메라 UDP5065/5066, 화면 UDP5067, 내 미리보기는 자기 PC loopback만 사용한다.
R 재대전과 인물 다시 선택은 같은 사람의 완료 수련을 유지한다.
사람을 바꾸고 C를 누르면 그 참가자의 수련만 다시 시작한다.

이번 확인 순서
1. 이전 게임과 Unity Play를 닫고 새 ZIP을 별도 폴더에 푼다.
2. 각자 앱/EXE를 실행. 스토리나 PvP에 들어가면 카메라는 자동 시작한다.
3. 보정 안내 문구가 실제 입력 상태와 맞는지 확인한다. 사람을 바꾸면 C를 누른다.
4. PvP에서 마우스/방향키 선택 → 선택 완료 → 수련 → 전투 진입을 확인한다.
5. 왼손 잽/오른손 스트레이트, 오른손 레이즈를 구분해 하고, 블락 후 펀치를 확인한다.
6. 충전 후 X자와 후속공격, KO 이후 R 재대전에서 수련을 다시 하지 않는지 확인한다.
7. Esc → 메인 메뉴 → 설정 → 기록 마무리 완료 → 진단 기록 저장.
   열린 DiagnosticsExports 폴더의 새 ZIP을 보낸다. PvP는 양쪽 ZIP이 필요하다.

남은 확인
촬영 없이 시행한 재생/자동검사는 실제 두 노트북 FPS나 사용자별 정확도를 보장하지 않는다.
발 접지·개별 필살기 화질은 이번 진단만으로 재현되지 않아 승인된 동작을 유지했다.
피/휴식 규칙은 사용자 요청에 따라 이번 수정에서 제외했다.
