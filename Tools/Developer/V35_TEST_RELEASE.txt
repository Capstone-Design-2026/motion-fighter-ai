REDBOOL v35 최종 확인용 시험판

게임: Unity6000.4.5f1 / 화면 protocol31
카메라: 검증된 v34.3 b5212300b62a9ff762a01df7a712e67ef3b11edf 유지
인식 기준·모델·개인 보정·공격 판정·입력 만료 조건 변경 없음.

주요 변경
- 인식/기술 시작, 피격에 의한 취소, 후딜, 충전 부족을 분리 표시.
- P2의 안내는 호스트가 결정한 자기 캐릭터 상태를 사용.
-5067 포트 점유 자동 복구, 새 연결 검증 전 전투 보류.
- 기존 저장 보호 확인, 음량/전체화면/3D 속도 우선/카메라 선택 설정.
- 운영자 I/F5/F6/F7/F8 및 수련 키보드 시험 기본 OFF.
- BGM d1514fce, 결과 화면 글꼴 9c656fa 선별 통합.
- READY/FIGHT 새 잠금은 기존 보정·PvP 시작을 보존하기 위해 미적용.
- 메인 메뉴에서 진단 저장 공간을 필요할 때만 확인. 자동 삭제 없음.

개발자
Unity 브랜치 codex/pvp-dual-screen-20261112를 사용.
카메라 별도 재학습/재빌드는 필요 없고 v34.3 native backend를 동봉.
RedboolLocalDemoBuild.Run으로 mac/windows 빌드 후 assemble_game.py 조립.
Python이 두 게임 화면을 렌더링하지 않으며 네트워크는 기존 LAN 방식 유지.
예전 v34 계열과 v35는 PvP 화면 protocol이 달라 혼용 불가.

검증
RedboolReleaseSelfCheck.Run: 입력/준비, 화면코덱, 수련 상태, 실제포트점유/복구,
설정·새게임 취소/확인, 전투 피드백 우선순위와 실제 공격중단 이벤트.
RedboolCameraNativeCheck: 패키지 실제 실행, synthetic bridge만 사용.
실제 카메라·노트북2대의 무선망 품질·체감 인식은 최종실제플레이에서 별도확인.
Development 빌드로 진단 가능한 시험판이며 정식 서명/스토어배포판 아님.

사용자 최종 한 번 확인
1 이전게임/Unity Play 종료. Mac REDBOOL.app 또는 Windows 전체압축해제 후 REDBOOL.exe 실행.
2 설정에서 전체화면/음량을 선택. 카메라가 다르면 번호선택 후 적용·다시연결.
3 스토리 이어하기 또는 빠른 대전. C 또는 보정 버튼, 사람 바뀔때만 새 보정.
4 블락→잽/스트레이트, 높은가드→양쪽레이즈, 충전후 X→후속공격.
5 상대에게 맞을 때 인식실패와 피격중단 안내가 구분되는지 확인.
6 PvP는 양쪽v35: 방만들기/방찾기, 수련 후 동시전투 및 재시작확인.
7 Esc→메인메뉴, 기록마무리 끝나면 진단기록저장. PvP 양쪽 ZIP 보관.
Esc 메뉴를 열어도 게임은 계속되므로 설정은 전투 전에 하는 것이 편합니다.
