# Mac 데모 빌드와 실제 플레이

2026-11-08 수련 진행 수정: [TutorialFix_20261108.md](TutorialFix_20261108.md). 각 기본 동작을 두 번 하면 다음 단계로 진행하며, X자는 수련 완료 후 전투에서 시험한다.

Unity 6000.4.5f1 프로젝트의 활성 Build Settings 16개 씬을 Mac 개발 빌드에 포함한다. Python 인식 프로그램은 별도로 실행하며 UDP 127.0.0.1:5065로 연결한다. 현재 Python 인식은 v11, Lite다. 실제 카메라/화면 확인은 빌드 성공과 별도로 수행한다.

## 로컬 실행

1. Unity 편집기 Play를 끈다. 같은 포트를 사용하는 다른 게임 실행을 함께 켜지 않는다.
2. REDBOOL.app을 연다. 저장된 진행이 있으면 이어하기, 처음이면 새 게임을 선택한다. 새 게임은 기존 진행을 초기화한다.
3. 지도에서 수련/전투로 들어가 Python 저장소에서 `bash scripts/run_seated_demo.command --host 127.0.0.1 --movement --seconds 600`을 실행한다.
4. 카메라 C로 최초 보정한다. Python을 계속 켜 두면 전투 전환 후에도 보정값을 유지한다. 카메라가 끊기면 게임은 준비 대기로 돌아간다.
5. 실제 2~3분 플레이에서 좌우 펀치, 양손 레이즈(각 하이킥/로우킥), 블락, 좌우 이동/중앙 정지, X자 필살기를 확인한다. 필살기 시험에는 게임 창 I 키로 충전(SPECIAL READY 확인), X자 약 1초 유지, 한 팔 레이즈/팔 분리 후 다음 공격을 사용한다.
6. 카메라 Q로 종료한다. 실행 중 원본 영상과 로그는 로컬에 저장된다.

## 재빌드

사용 중인 Unity 프로젝트 대신 Assets, Packages, ProjectSettings를 복사한 별도 디렉터리를 사용한다. 원본 프로젝트를 동시에 batchmode로 열지 않는다. 출력 경로를 `REDBOOL_BUILD_OUTPUT` 환경 변수에 지정하고 Unity의 `-batchmode -quit -projectPath <복사본> -executeMethod RedboolLocalDemoBuild.Run -logFile <빌드로그>`로 실행한다. 빌드 메서드는 `build-result.txt`와 단계별 `build-messages.txt`를 출력한다. 개발 플러그인의 자동 연결이 필요 없다면 실행 프로세스에 `UNITY_MCP_DISABLE=1`을 설정할 수 있다.

`-nographics`는 현재 프로젝트의 빌드 중 미리보기 초기화 오류를 남기므로 최종 그래픽 확인용 빌드에서는 사용하지 않는다. 실행 확인용 복사본은 로컬 패키지 상태를 포함한다. 배포 바이너리와 Library/원본 촬영은 Git에 올리지 않는다.

## 남은 확인

모든 씬을 빌드에 넣었다고 모두 플레이 검증한 것은 아니다. 새 v11의 첫 X자 체감, 전투 간 보정 유지, 실제 화면 움직임/연출, 저장·이어하기와 스테이지 흐름을 실제 플레이로 확인한다. 상세 인식 결과는 MotionFlow_20261107.md를 참조한다.
