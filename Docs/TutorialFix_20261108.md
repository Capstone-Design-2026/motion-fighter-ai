# 수련 첫 잽에서 진행되지 않는 문제 수정

2026-11-08 03:32 촬영은 LEFT_PUNCH 22회, RIGHT_PUNCH 2회가 인식되어 Unity에 TUTORIAL_APPLIED로 전달됐지만 수련 첫 단계 성공은 0이었다. TUTORIAL_APPLIED는 수련 콜백에 전달됐다는 뜻이며 수련 성공 횟수 증가를 보장하지 않는다.

## 원인과 변경

수신기가 공격 상태 READY 외의 CANDIDATE/ACTIVE/RETURNING까지 UNAVAILABLE로 바꿔 전달했다. 따라서 펀치 후보가 시작되자 수련의 준비 여부가 꺼지고, 이어 도착한 유효한 펀치를 거절했다.

- 보정·관절 추적·입력 만료 여부와 공격 중간 상태를 구분한다. 보정되지 않거나 추적이 끊긴 상태에서는 수련 공격도 INPUT_LOCKED로 거절한다.
- 잽/스트레이트/하이킥/로우킥은 Python이 각 팔의 회수·내림을 확인한 뒤 보내고 수신기가 event_id로 중복을 제거하는 단발 입력이다. 수련에서 다시 양손 가드 복귀를 요구하지 않는다.
- 블락과 이동은 연속 상태이므로 팔 내림/중앙 복귀를 확인한 뒤 다음 성공을 센다. 이동 도중 공격 패킷의 임시 NEUTRAL 필드로 중앙 복귀를 인정하지 않는다.
- 시범 중 입력, 다른 기술, 같은 event_id 재전송은 성공을 늘리지 않는다. 키보드 테스트는 별도 모드이며 기존 Space 준비 동작을 유지한다.
- 카메라와 같은 Mac에서 실행하는 게임에 60fps 제한을 둔다. 기존 설정은 vSync=0에 프레임 제한이 없었다. 최신 촬영에서 처리 누락 프레임은 1,653/7,362였으며 렌더 제한 이후 실제 카메라 부하는 다시 측정해야 한다.

## 사용자 확인

기존 게임을 완전히 종료하고 새 실행 파일을 연다. 이어하기 → 동굴 수련으로 들어가 카메라 C로 최초 보정한다. 각 단계의 시범이 끝난 뒤 안내 동작을 두 번 수행한다. 성공 표시가 0/2 → 1/2 → 2/2로 올라가면 다음 단계로 자동 진행한다. 펀치는 뻗고 회수, 레이즈는 올리고 내림, 블락은 올리고 내림, 이동은 기울이고 중앙 복귀를 두 번 한다.

수련은 7개 기본 기술이며 X자 필살기는 여기서 세지 않는다. 수련을 끝내고 전투에 들어간 후 충전/X자/후속 공격을 확인한다. Python이 계속 켜져 있으면 전투로 넘어가도 보정을 다시 할 필요 없다.

## 검증 방식

RedboolTutorialPlayCheck는 별도 Unity 복사본에서 실제 수련 UI와 UDP 수신기를 켜고 포트 15065로 명령을 보낸다. 원래 진행 데이터는 검사 종료 시 복원한다. 원본 코드에서는 READY→CANDIDATE→ACTIVE→LEFT_PUNCH 순서에서 첫 성공이 올라가지 않는 실패를 재현했다. 수정본에서는 7단계, 중복, 잘못된 동작, 보정 미완료/추적 끊김, 연속 유지 중 중복 성공 방지를 확인한다. 이 검사는 합성 입력의 수련 연결 검증이며 실제 사람의 인식 정확도 측정은 아니다.
