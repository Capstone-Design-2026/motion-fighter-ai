# PvP 대기실 · 인물 선택 · 설명형 수련

2026-11-14. PvP에 들어온 뒤 싸우기 전까지의 흐름을 만들었다.

```
PvP 대전(방 만들기 / 대전 참가)
  → 대기실: 두 사람의 카메라(두 화면 대전이면 2P 화면도)가 준비될 때까지 기다린다
  → 인물 선택: 12명 가운데 각자 한 명
  → 수련(튜토리얼): 8가지 동작을 설명을 보며 두 번씩 따라 한다
  → 대전
```

브랜치 `feature/pvp-lobby-tutorial` = 웅빈의 PvP 브랜치(`codex/pvp-dual-screen-20261112`) + 최신 `feature/unity`(적 동작·적 필살기·새 무대). 두 브랜치를 합칠 때 충돌은 두 파일이었다(`StartSceneUI.cs`는 양쪽 필드를 모두 남김, `HeroJabPlayCheck.cs`는 PvP 쪽 검사를 남김).

## 대기실

두 사람의 카메라 신호가 잡히면(두 화면 대전이면 2P 화면 연결도 되면) 자동으로 인물 선택으로 넘어간다. 진행자는 호스트에서 F9로 바로 넘길 수 있다.

## 인물 선택

주인공 청운과 스토리의 적 11명. 처음 칸은 1P 청운, 2P 철문(기존 PvP와 같은 조합)이다.

| 하는 일 | 카메라 동작 | 호스트 키보드 (진행자용) |
| --- | --- | --- |
| 칸 옮기기 | 몸을 좌우로 기울이기 (기울이고 있으면 0.6초마다 한 칸) | 1P: A / D, 2P: ← / → |
| 확정 | 잽 또는 스트레이트 | 1P: F, 2P: Enter |
| 취소 | 양손 막기 | 1P: G, 2P: Backspace |

- 제한 시간 45초. 한 사람이 먼저 확정하면 남은 사람에게 15초만 준다. 시간이 다 되면 고르고 있던 칸으로 확정된다.
- 둘 다 확정하면 1.2초 뒤 인물이 입혀지고 수련으로 넘어간다.
- 고르는 동안에는 인물이 걷지 않고, 그 동작이 수련으로 세어지지도 않는다. 카메라 프로그램에는 수련 단계 대신 `phase = "SELECT"`를 알려 개인 보정이 이 동작을 표본으로 쓰지 않게 했다.
- 대전이 끝난 화면에서 F8을 누르면 같은 두 사람이 인물만 다시 고른다(수련은 다시 하지 않는다).

### 인물을 고르면 바뀌는 것, 안 바뀌는 것

PvP의 두 사람은 모두 주인공의 조작부(`PlayerController`)로 움직인다(기존 구조). 인물 선택은 그 위에 **겉모습과 그 인물의 동작 세트**를 입힌다.

- 바뀐다: 모습, 동작(각 인물의 Animator), 체력 패널의 이름.
- 안 바뀐다: 체력, 공격력, 판정, 이동 속도. **필살기는 모두 파운장이다.**

적 11명의 고유 필살기(`EnemySpecial`)는 AI 적이 주인공에게 쓰는 전제로 만들어져 있어서(오른쪽에 선 적, 게이지가 차면 자동 발동, 손님 화면으로 보내는 연출 없음) PvP에는 아직 연결하지 않았다. 선택 화면에는 고유 필살기 이름과 함께 "대전에서는 아직 파운장으로 나갑니다"라고 적어 두었다. 명단(`RedboolPvpRoster`)에 이름이 들어 있으니, 연결할 때 여기서 고르면 된다.

## 수련 (튜토리얼)

무엇을 몇 번 했는지는 기존 `RedboolPractice`가 그대로 판단한다. 순서(잽, 스트레이트, 하이킥, 로우킥, 막기, 왼쪽 이동, 오른쪽 이동, 필살기)와 "두 번씩" 규칙은 카메라 쪽 개인 보정과 맞물려 있어 바꾸지 않았다.

달라진 것은 화면이다. 각자 자기 쪽 절반에 설명 카드가 뜬다.

- 제목: `수련 3 / 8   하이킥`
- 단계: ① 시범 보기 → ② 따라 하기 → ③ 돌아오기 (지금 단계가 밝게 표시된다)
- 동작 방법: "왼손을 머리 위로 들어 올렸다가 내리세요"
- 쓰임: "머리를 노리는 발차기. 느리지만 멀리 닿습니다"
- 성공 횟수: ● ○
- 상황에 맞는 한 줄: 처음에는 "그림을 먼저 보세요", 한 번 성공하면 "같은 동작을 한 번 더", 9초 넘게 못 하면 도움말, 카메라 신호가 없으면 그 안내
- 그림: 기존 "나의 동작" 옆에 "게임 속 동작"을 나란히

스토리 모드의 `CaveTutorial`과 같은 짜임이다. 글은 `RedboolPvpTutorialCard.cs`의 `Names`, `How`, `Use`, `Tips`에 모여 있다.

## 2P 화면(손님)

판단은 호스트만 한다. 손님 화면은 호스트가 보낸 값으로 같은 화면을 그린다(대기실, 인물 선택의 두 테두리와 남은 시간, 수련 카드). 인물 번호가 바뀌면 손님 쪽 두 사람에게도 같은 겉모습을 입히고 뼈대를 다시 잡는다.

프로토콜 버전이 30으로 올라가서, 두 노트북의 게임이 같은 빌드여야 연결된다.

## 켜고 끄기

- 실제 실행에서는 켜져 있다. 끄려면 `--redbool-pvp-no-lobby`.
- 자동 검사(배치 실행)에서는 꺼져 있다. 기존 PvP 검사들이 예전 흐름(바로 수련) 그대로 통하게 하기 위해서다. 켜려면 `-redbool-pvp-lobby`.

## 확인하는 법

```
Unity -batchmode -projectPath <프로젝트> -executeMethod RedboolPvpLobbyCheck.Run -redbool-pvp-lobby
환경변수 REDBOOL_LOBBY_CHECK_OUTPUT=<빈 폴더>
(두 화면까지 보려면) REDBOOL_DUAL_CLIENT=<빌드한 REDBOOL.exe>
```

실제 카메라는 열지 않고 UDP 5065/5066으로 가짜 신호를 보낸다. 결과는 `checks.txt`, `result.txt`, 단계별 화면(png).

## 2026-11-14 확인한 것

- `RedboolPvpLobbyCheck`(가짜 카메라 신호): 한 화면 68개, 두 화면(빌드한 게임을 2P 화면으로 띄움) 74개 모두 통과. 대기실 → 인물 선택(기울여 옮기기, 계속 기울이기, 잽·스트레이트 확정, 막기 취소, 15초 단축, 고르는 동안 걷지 않음·수련으로 세지 않음) → 인물 입히기 → 수련 8동작 → 대전 시작 → 대전 중 걷기·잽 → 주인공으로 되돌리기.
- 2P 화면: 손님 게임이 남긴 화면에서 대기실, 인물 선택, 수련 카드, 고른 두 인물을 눈으로 확인했다. 손님 기록에 실행 오류가 없었다.
- 기존 검사: `RedboolPvpPlayCheck` 94개 통과(대기실을 끈 예전 흐름), `RedboolViewSelfCheck` 3954개 통과(가장 큰 조각 602바이트, 한 프레임 1792바이트).
- 실제 카메라로 사람이 해 본 것은 아니다. 두 대의 노트북으로도 해 보지 않았다(한 PC에서 두 게임으로 확인).

## 알아둘 것

- **전투 효과 준비가 가끔 끝나지 않는다(기존 문제).** `RedboolRenderWarmup`의 코루틴이 시작만 하고 다음 프레임에 이어지지 않는 일이 배치 검사에서 4~6번에 1번꼴로 나온다. 그러면 "전투 효과 준비 중"에서 넘어가지 않아 대전이 열리지 않는다. 대기실을 넣기 전의 순수 병합 상태에서도 6번 중 1번 나왔으므로 이 작업과 무관하다. 원인은 찾지 못했다. `RedboolPvpLobbyCheck`는 이 경우를 따로 가려내 알려 준다(그때는 다시 돌린다). 빌드한 게임에서도 생기는지는 확인하지 않았다.
- 인물 선택에서 같은 인물을 둘 다 고를 수 있다. 구별은 체력 패널의 이름과 자리(1P 왼쪽, 2P 오른쪽)뿐이다.
- 손님 화면에서는 마우스·키보드로 인물을 고를 수 없다(카메라 동작은 호스트로 가므로 된다). 진행자 키보드는 호스트에서만 듣는다.
- PvP 무대는 그대로 `ScoutPass`다. `feature/unity`에 만든 PvP 전용 맵(지하 동굴 투기장)을 쓰려면 `RedboolDuelTest.ArenaScene`을 바꾸고, 그 이름을 직접 적어 둔 검사 문장(`RedboolPvpPlayCheck`의 "ScoutPass")도 같이 고쳐야 한다.
