# v27: 개인 수련 보정과 LAN 2인 대전

기준: Python v26 `0d831d1`, Unity `c71dae0`.
기존 v26 배포본은 별도 보관한다. 원본 녹화와 모델 가중치는 변경하지 않는다.

## 구성

- 호스트 Mac: Unity 게임 하나 + P1 카메라 인식. UDP 5065 / actor P1.
- 두 번째 노트북: P2 카메라 인식. 호스트 IPv4의 UDP 5066 / actor P2.
- 영상은 네트워크로 보내지 않는다. 각 노트북이 자신의 관절을 추정하고 동작·상태와 수신 확인만 주고받는다.
- 두 캐릭터는 ScoutPass 실제 결투장에 함께 존재한다. 게임의 위치·충돌·피해·라운드는 호스트 Unity만 판정한다.
- 현재 두 번째 노트북에는 카메라 창이 뜬다. 양쪽 Unity 화면 동기화는 포함하지 않는다. 시연에서는 호스트 화면 또는 연결된 큰 화면을 함께 본다.
- 스토리는 기존 DEV01 / 5065로 유지한다. 두 모드의 게임을 동시에 실행하지 않는다.

## 개인 보정

`--personal-calibration`을 명시했을 때 켜진다. 플래그가 없으면 기존 v26 인식 경로다.
튜토리얼은 잽, 스트레이트, 왼손/오른손 레이즈, 블락, 좌/우 이동, X자 순서이며 각 동작 2회다.
Unity는 현재 수련 단계·연습/복귀 상태를 ACK로 알린다. 키보드 시범은 학습 예시가 아니다.

- 중앙 가드에서 시작해서 동작을 하고 복귀한 두 번의 일관된 관절 궤적만 보정에 쓴다.
- 단순히 해당 동작 안내가 떠 있었다는 이유로 정답으로 기록하지 않는다. 가림·다른 동작·불안정한 반복은 제외한다.
- 아직 인식 이벤트가 발생하지 않은 동작도 별도의 기하 조건을 만족하면 보정 후보가 된다. 보정 자체가 성공 횟수를 만들어 내지는 않는다.
- 어깨 폭으로 정규화한 펀치 확정 이동량 .28–.32, 레이즈 높이 .36–.40, 블락 상승량 .29–.32, 이동 진입량 .18–.22 범위에서만 조절한다.
- 관절 신뢰도, 팔 펴짐 증거, 복귀/재무장, X자 소유·700ms 유지·해제, 공격 유효기간은 완화하지 않는다.
- X자는 수련에서 확인하지만 두 예시만으로 X의 기하 임계값이나 모델 가중치를 재학습하지 않는다.
- 데이터가 부족하면 해당 동작은 기본 v26을 쓴다. 적용된 범위와 표본 수는 기록 폴더의 `personal_profile.json`에 남긴다.
- 프로필은 현재 사람/실행 안에서만 유지한다. C를 누르면 기본 보정과 개인 범위가 초기화된다. 다른 사람으로 교체할 때 C를 누른다.
- PvP에서 C 또는 새로운 카메라 실행이 확인되면 그 참가자의 수련만 다시 시작한다. 재대전에는 C나 수련을 반복하지 않는다.
- 이것은 제한적인 개인 범위 보정이며, 사용자별 새 인식 모델을 학습했다고 표현하지 않는다.

## 대전 진행

1. 호스트에서 새 게임 메뉴의 `2인 대전 · 카메라 연결`을 누르거나 빌드에 `--redbool-pvp`를 준다.
2. 각 노트북의 자기 카메라를 켜고 C로 중앙 가드를 보정한다.
3. 각자 화면 안내 동작을 두 번씩 하고 팔/몸을 중앙으로 돌린다. 먼저 끝낸 사람은 기다린다.
4. 둘 다 수련을 마치고 중앙 가드가 1초 확인되면 120초 라운드가 시작된다.
5. 블락은 유지 중에만 적용한다. X자 파운장은 피격으로 충전된 뒤 사용할 수 있다. 수련에서 X자는 충전 없이 연습한다.
6. 연결·추적·보정 상태가 끊기면 양쪽 입력·피해·시간이 멈춘다. 만료된 공격은 재생하지 않는다. 미발사 필살기는 중단 시 충전을 복원한다.
7. KO/시간 초과는 체력 비교로 판정하며 같은 체력은 무승부다. R로 재대전, Esc로 메뉴로 돌아간다.
8. PvP는 스토리 저장/삭제 호출도 차단한다. PvP의 파운장에는 서로 충돌하는 전체 화면 컷인·슬로우·줌을 적용하지 않으며 캐릭터·기파·타격은 유지한다.

## 기존 저장소에서 카메라만 실행

활성화된 Python 3.11 환경, Lite/Full 모델이 필요하다. 카메라 전용 의존성은 기존 `requirements-pilot-windows.txt`와 같다.

```bash
python scripts/run_personal_camera.py --check
python scripts/run_personal_camera.py --player 1 --host 127.0.0.1
python scripts/run_personal_camera.py --player 2 --host HOST_IPV4
```

`HOST_IPV4`를 게임을 실행하는 Mac의 현재 LAN IPv4로 바꾼다. 같은 네트워크를 사용하고 호스트의 Unity 수신 UDP 5065/5066을 허용한다. 인터넷 포트 전달은 하지 않는다.
스토리 카메라는 `--player story`를 쓴다. 이전 v26 명령은 그대로 사용할 수 있다.

## 검증 범위와 남은 확인

카메라 없이 기존 녹화 재생, 합성 관절, 실제 Unity UDP/공격·접촉·이동·필살기·수련·재대전·스토리 저장 검사를 수행한다.
개인 보정을 적용하지 않은 여러 사람 기록 3개에서 98/89/86개 이벤트가 v26과 발생 프레임까지 동일하다.
기존 프레임과 정답이 없는 자유 플레이만으로 새 사람의 정확도 상승률을 산출하지 않는다.

실제 두 노트북의 카메라·LAN·방화벽·발열과 2인 동시 플레이는 현장 최종 확인 대상이다.
한 호스트 화면을 공유하는 구성이다. 두 개의 게임 화면, 온라인 매치메이킹, 인터넷 대전, 얼굴 기반 사람 식별, 영구 자동 프로필 선택은 포함하지 않는다.
