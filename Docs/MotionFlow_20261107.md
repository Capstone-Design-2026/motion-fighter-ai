# v10: X자에서 한 팔 레이즈로 바로 연결 (2026-11-07 23:39 촬영 반영)

현재 엔진은 seated-cross-release-20261107-v10, 기본 관절 모델은 Lite다. 아래 v9 설명보다 이 변경이 우선한다.

- 한쪽 손목을 X자 영역보다 확실히 위로 올리면 다른 팔이 가슴에 남아 있어도 X자 해제로 인정한다. 양쪽 손목 분리와 양팔 내림도 해제 동작이다. 유효한 양팔 관절과 180ms 해제 확인은 유지한다.
- 그래서 X자 → 한 팔 레이즈 → X자를 중간 양손 가드 없이 이어 쓸 수 있다. 유지 중인 X자 자체를 반복 발동시키지는 않는다.
- 카메라 창에 GAME READY/BUSY와 SPECIAL READY/NEEDS CHARGE, X자 유지 진행률, 인식된 X자 요청 수를 표시한다. 게이지 상태는 Unity의 최신 응답으로 확인하고 오래된 응답은 UNKNOWN으로 표시한다. 표시되는 X 횟수는 게임 실행 성공 횟수가 아니다.
- Unity 프로토콜·게이지 소모·게임 후딜은 바꾸지 않았다. 거절된 입력을 나중에 자동 실행하지 않는다.

## 이번 촬영의 실제 결과

총 37개 인식 이벤트 중 Unity 적용 25개. X자 요청 11개는 실행 응답 3개, 게이지 부족 6개, GAME_BUSY 2개였다. 일반 기술 26개는 적용 22개, GAME_BUSY 4개였다. 입력 누락과 게임 거절을 구분해야 한다.

첫 번째로 영상에서 확인한 X자 5회는 당시 4회 인식/1회 누락이었다. 인식된 4회 중 실제 실행 응답은 1회이고 3회는 NOT_CHARGED였다. 그 뒤 레이즈 5회는 당시 3회 인식됐으며 2회 적용/1회 GAME_BUSY였다.

수정 후 동일 영상 재생에서는 해당 X자 5회와 다음 레이즈 5회를 각각 1회씩 인식한다. 전체 X자는 11→14개, 레이즈는 21→26개이며 추가 이벤트를 주요 영상 구간과 대조했다. 이전 21:17 촬영의 이벤트 결과도 유지했다. 이는 같은 개발 영상의 사후 재생 개선이며 새 촬영 성공률이나 Unity 실행 5회 성공을 의미하지 않는다. 일부 다른 X자 구간의 불안정한 관절/유지 조건으로 인한 누락은 여전히 남아 있어 모든 시도가 해결됐다고 보지 않는다.

가드 없이 이어 쓰기는 실제 세 기술이 연속 APPLIED된 두 묶음(촬영 첫 저장 프레임 기준 약 110.24→111.58→113.19초, 116.37→117.74→119.39초)에서 확인됐다. 그 사이 인식 상태가 READY인 프레임은 없었다.

이번 기록은 블락 입력이 0회라 블락 성공을 판정할 수 없다. Unity 화면 녹화가 없어 실제 화면의 연출/체감 지연은 미검증이다.

## 다음 시험: 충전 확인 후 5회

기존 카메라 창을 Q로 종료한 뒤 같은 실행 명령으로 다시 실행하고 C로 최초 보정한다. Unity는 같은 전투 씬에서 Play를 유지한다.

1. 카메라 창에서 GAME READY를 확인한다.
2. Unity Game 화면을 클릭해 I를 눌러 충전한다. 매회 SPECIAL READY 표시를 확인한다. 한 번 실행하면 게이지가 소비되므로 다시 충전해야 한다.
3. 가슴 앞 X자 1~2초 → 다른 팔은 가슴에 두고 한 팔 레이즈 → 팔을 내려 다음 동작. 양손 가드에 멈출 필요 없다.
4. 총 5회 반복하되 게임이 BUSY일 때 시도한 것은 별도로 기록한다. 블락 3회와 편한 대기 10초를 추가하고 카메라 창 Q로 종료한다.

# 2026-11-07 v9: X자 필살기와 동작 연결 보완

현재 기본은 Lite + seated-flow-cross-20261107-v9다. Unity UDP 규약과 기존 수신기는 바뀌지 않았다.

## 조작 변경

- C로 최초 보정하고 Python을 계속 켜 두면 다음 전투에서도 보정값을 유지한다.
- 레이즈 후 양손을 정확한 가드 위치로 돌릴 필요가 없다. 각 손을 내렸는지 따로 판정하고, 다른 손 기술로 연결할 수 있다.
- 펀치는 해당 팔을 몸 가까운 굽힌 자세로 회수하면 다시 준비한다. 펼친 팔을 계속 유지하거나 시간만 지났다고 재발동하지 않는다.
- X자는 가슴~턱 아래 높이에서 양팔을 교차해 유지한다. 이전의 낮은 가슴 높이만 허용하던 조건을 보완했다. 양쪽 어깨·팔꿈치·손목이 화면 안에 보여야 한다.
- 양손이 중앙으로 모이는 단계부터 X자 후보가 입력을 소유해 일반 펀치가 먼저 나오지 않게 한다. 확인된 X자 시간 0.7초가 필요하고 짧은 기하 판정 흔들림은 시간을 더하지 않고 보류한다. 관절 누락/긴 프레임 단절은 유지 시간을 초기화한다.
- X자를 유지하면 1회만 요청한다. 팔을 분리한 자세가 확인되면 다음 동작으로 넘어갈 수 있으며, 꼭 보정 가드 자세일 필요는 없다.
- BLOCK 후 한쪽 손만 내리고 다른 손을 계속 들고 있어도 그것을 새 킥으로 만들지 않는다. 새 레이즈는 해당 손의 내려감이 먼저 확인되어야 한다.
- 카메라 창 X 키는 인식 일시정지/보정 해제, Q는 종료다. 몸으로 만드는 X자와 다르다.
- 가드 복귀 제한 완화와 Unity 후딜은 별개다. 피격·공격 후딜·KO 등에는 GAME_BUSY가 올 수 있다. 거절된 공격을 나중에 몰아서 실행하지 않는다.

## 검증 및 한계

2026-11-07 21:17 촬영을 원본 관절·촬영 시각·C 보정 순서대로 재생했다. 기존 SPECIAL 0건에서 13건으로 증가했고, 198.64초 X자 진입에서 나오던 펀치 입력은 사라졌다. 영상으로 확인한 마지막 X자 5회는 각 1회 인식했다. 이 세션은 수정에 사용한 개발 자료이므로 독립 검증 정확도나 새 촬영 성공률이 아니다.

기존 펀치·레이즈·블락·이동·가드 복귀 기록, 중복 방지·가림·통신·보정 검사를 포함한 104개 검사가 통과했다. 새 실제 X자 회귀 3개도 통과했다. 중간 가드 없는 좌우 레이즈, X자→레이즈→X자, 편한 한손 회수, 유지 중 중복 방지를 포함한다. 기존 19:09 왼손 레이즈 5회도 보존됐다.

같은 RGB 8,382프레임에 Full 모델을 다시 적용했으나, 같은 수정 규칙의 X자 이벤트는 Lite 13건/Full 11건이었다. 동작별 정답 총수가 확정된 정확도 비교는 아니며 기본 모델을 바꿀 근거로 삼지 않았다. 기존 Lite를 유지한다.

모든 X자 시도가 해결된 것은 아니다. 팔꿈치가 화면 밖으로 나가거나 관절 추정이 흔들리는 구간에서는 여전히 누락될 수 있다. 이번 수정은 규칙·동작 상태 처리 보완이며 모델 재학습이 아니다. 변경 후 실제 카메라→Unity 플레이는 짧은 새 시험이 필요하다.

## 실행과 다음 시험

Unity GameScene Play 상태에서 Python 저장소의 scripts/run_seated_demo.command --host 127.0.0.1 --movement --seconds 600을 실행한다. 실행하면 원본 처리 영상·관절·인식·통신 로그가 로컬에 저장된다.

1. 카메라 창 C로 보정한다.
2. 좌우 펀치, 왼손 레이즈→오른손 레이즈→펀치를 이어서 3묶음 실행한다. 매번 양손 가드에 멈추지 않아도 된다. 같은 손은 회수/내림, X자는 팔 분리가 필요하다.
3. Unity Game 화면 I를 5번 눌러 SPECIAL READY를 확인하고 X자→팔 분리→레이즈를 시험한다. 재충전하며 X자를 총 5회 시도한다.
4. 얼굴 앞 블락과 X자를 번갈아 3회, 마지막 편한 대기 10초를 기록하고 카메라 창 Q로 끝낸다.
5. 누락/오발동과 화면에서 GAME_BUSY였던 경우를 구분해 기록한다.
