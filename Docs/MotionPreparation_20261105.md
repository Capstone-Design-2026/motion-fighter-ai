# 최초 보정 유지, 전투 자동 연결, X자 필살기

전투 씬이 로드되면 PlayerController/Fighter를 찾아 모션 수신기와 준비 제어기를 자동 연결한다. 모든 대상 전투 씬에 개별 설치할 필요가 없다. 같은 포트의 중복 수신기는 비활성화하고 예전 5055 수신기가 입력을 덮어쓰지 않게 한다.

## 보정은 Python 실행 중 처음 한 번

- Python 카메라 창에서 C로 앉은 가드 자세를 보정한다. 보정 과정 자체는 안정된 자세를 수집한다.
- 별도의 2초 준비 자세 유지 조건은 제거했다. 보정 완료와 유효한 현재 영상이 확인되면 전투를 시작한다.
- 같은 Python 실행을 유지하는 동안 다음 전투에서도 보정값을 그대로 사용한다. 씬 전환 때는 새 연결의 최신 STATE만 확인하고 자동 재개한다. 과거 ACK나 Unity에 저장된 오래된 준비 여부만으로 전투를 시작하지 않는다.
- 추적/연결이 0.5초 이상 끊기면 적·플레이어·라운드 시간을 대기시키고 유효한 현재 영상이 돌아오면 기존 보정값으로 재개한다.
- 구도나 의자 위치가 달라져 잘 맞지 않을 때 C로 재보정한다. X는 인식 중단/보정 해제다. Q로 Python을 종료하면 전투가 대기한다.
- Python을 종료하고 새로 실행하면 처음 한 번 다시 보정한다. 개인 보정값을 디스크에서 무조건 불러오는 기능은 추가하지 않았다.
- 준비 잠금은 KO/스토리 잠금과 별개이며 해당 잠금을 해제하지 않는다. 기존 공격·방어 후딜도 우회하지 않는다.

## 필살기

가슴 앞에서 양팔을 X자로 교차하고 0.7초 유지한다. 손목은 어깨선보다 조금 아래, 팔꿈치는 손목보다 아래에 놓여야 한다. 양쪽 손목이 반대쪽 어깨 방향으로 넘어간 모양을 양쪽 어깨·팔꿈치·손목 좌표로 판정한다.

- 얼굴 높이 블락, 한손 레이즈와 구분하는 규칙이다. 후보 상태와 복귀 중에는 일반 펀치·킥·블락을 함께 내보내지 않는다.
- 먼저 보정된 준비 자세를 확인한 뒤 요청을 받는다. 한 번 발동한 뒤에는 실제 준비 자세 복귀가 있어야 다시 발동한다. 가림·프레임 단절로 유지 시간을 이어붙이지 않는다.
- 프로토콜: GESTURE / gesture=SPECIAL / side=BOTH. 기존 150ms 이벤트 유효기간과 동일 ID 중복 방지를 유지한다.
- Unity의 기존 SpecialMove를 호출한다. 게이지 부족은 NOT_CHARGED, 현재 행동 불가는 GAME_BUSY로 보고하고 나중에 자동 재생하지 않는다. 수련 중 필살기는 현재 7단계 과제에 포함하지 않는다.
- 실제 X자 촬영 자료로 학습한 분류기가 아니라 새 기하 규칙이다. 모의 관절·기존 촬영 회귀는 통과했지만 사람의 X자 촬영에서 인식 여부와 블락 혼동을 확인해야 한다.

## 실행

Unity에서 GameScene을 열고 Play를 누른다. 같은 Mac의 Python 저장소에서:

```bash
bash scripts/run_seated_demo.command --host 127.0.0.1 --movement --seconds 600
```

카메라 창 C로 처음 보정한다. 이후 씬이 바뀌어도 Python은 계속 실행해 둔다. 카메라 실행은 원본 영상과 인식 로그를 로컬 세션에 저장한다. Unity의 I 키는 기존 필살기 게이지 충전 테스트 키이며 실제 플레이에서는 피격으로 충전된다. 필살기를 시험할 때만 사용한다.

STATE의 calibration_version=1 / calibrated 필드가 있는 최신 Python과 함께 사용한다. ACK의 calibration_contract / battle_preparing / special_ready로 현재 상태를 확인할 수 있다. 합성 probe는 적과 시간을 대기시킨 채 플레이어 기술을 검사한다. 실제 적중/피해 검사는 실제 플레이에서 별도로 확인한다.

## 검증 결과와 남은 범위

- Python 99개 검사 통과. X자/블락/한손 레이즈 구분, 0.7초 유지, 복귀·가림·중복 방지, 통합 인식 엔진, 게이지 부족 등의 거절 시 대기 요청 제거, 기존 촬영 회귀 포함. 실제 카메라는 열지 않았다.
- Unity 실제 프로젝트 임포트와 컴파일, 입력 정책/매핑 23개 검사 통과.
- Unity 배치 Play에서 GameScene과 ScoutPass의 18개 검사 통과: 자동 연결, 보정 전 적·플레이어·시간·HP 대기, 보정 즉시 시작, KO 잠금 보존, 재보정, 합성 검사 모드, 필살기 게이지 부족/충전/한 번 소비, 다음 씬에서 보정 재사용. 기존 진행 저장 보존 확인.
- Play 검사는 준비 제어기에 테스트 상태를 전달하고 실제 SpecialMove 루틴을 실행했다. 전체 카메라→UDP→화면 경로, 필살기 실촬영 인식률, 화면 품질·체감 지연까지 검증한 것은 아니다.
- 개발 검증 메뉴: Tools > REDBOOL > Run Input Adapter Self Check / Check Battle Auto Connection (Play Mode).
- 배치 Play 검사는 -executeMethod RedboolMotionPlayCheck.Run으로 실행하며 테스트 종료 시 Editor가 종료된다. 일반 작업 중 실행하지 않는다.

## 2026-11-07 Mac 실제 UDP 추가 검증

현재 로컬 패키지 상태에서 다시 컴파일하고 배치 Play 21개 검사를 통과했다. 실제 Python 송신기에서 Unity 수신 소켓으로 일반 기술 4종과 시간제 가드를 전송해 모두 적용된 것을 확인했다.

합성 관절을 실제 SixGestureEngine에 넣어 보정 → X자 유지 → 가드 복귀를 실행했다. 생성된 SPECIAL/BOTH 이벤트가 실제 UDP로 전달되어 게이지 부족 시 NOT_CHARGED, 충전 후 APPLIED/SPECIAL로 응답됐다. 같은 이벤트를 두 번 보내도 Unity 적용 횟수는 1회였고 게이지가 소비됐다. 이 검사는 사람의 X자 인식률이나 화면 지연 검사가 아니다.

재현: 기존 Python 저장소의 venv와 src:tests PYTHONPATH를 사용한다. 비어 있는 동일 출력 폴더를 Unity 환경 변수 REDBOOL_UDP_CHECK_DIR와 Tools/check_motion_udp.py의 위치 인수로 전달한다. Unity는 위 배치 Play 진입점으로 실행하고, Python 도구는 별도 프로세스로 병행 실행한다. 도구는 최대 240초 동안 Unity 준비를 기다리고 카메라는 열지 않는다. 일반 GUI Play나 진행 중인 게임에 사용하지 않는다. 기존 진행 저장은 배치 검사 종료 시 복원된다.

사람 시험: GameScene의 Play를 켜고 Python 카메라를 실행한 뒤 카메라 창 C로 최초 보정한다. 게임 화면 I를 5번 눌러 테스트 게이지를 채우고 SPECIAL READY를 확인한다. 중앙 가드에서 가슴 앞 X자를 0.7초 이상 유지한 뒤 가드로 돌아온다. 다섯 번 반복하고 얼굴 앞 블락과도 번갈아 비교한다. 키보드 X는 필살기가 아니라 보정 해제/일시정지이므로 구분한다.
