# REDBOOL 데모 v7: 실제 학습과 선택 결과 — 2026-11-04

기본 실행은 **MediaPipe Lite + 보정 기반 v7 인식기**입니다. 실제 학습한 분류기도 비교했지만, 현재 연속 동작에서는 기존 방식을 보완한 쪽이 더 안정적이었습니다. 모델 학습 완료와 데모 기본 모델 채택은 별개입니다. 기존 V1 모델과 촬영 원본은 보존했습니다.

## 실제로 학습한 것

- 최근 촬영 4세션을 영상으로 검토했습니다. 14:04·14:39는 학습, 15:47은 모델 선택용 검증, 16:17은 학습에서 제외한 세션 평가입니다. 16:17의 실패는 이미 규칙 수정에 참고했으므로 새로운 블라인드 시험은 아닙니다.
- 각 세션을 통째로 나눴습니다. 같은 촬영의 이웃 프레임을 무작위로 학습/평가에 섞지 않았습니다. 16:17 자료는 가중치·표준화 학습에 넣지 않았습니다.
- 구간 라벨은 영상에서 확인한 보수적인 자세 구간입니다. 안내 문구나 기존 인식 결과를 정답으로 복사하지 않았습니다. AI 보조 검토이며 독립적인 사람 검수는 아직 없습니다. 늦게 수행한 펀치는 뒤의 GUARD 구간까지 확인했고, 실제로 하지 않은 첫 오른손 레이즈는 평가 분모에서 제외했습니다.
- GUARD, NONE, 좌우 펀치, 좌우 레이즈, BLOCK의 7종을 학습했습니다. 왼손 내리기는 게임 입력에서 제외된 음성 사례(NONE)로 사용했습니다. 이동은 별도의 몸 기울임 인식기를 유지합니다.
- 과거 400ms의 관절 위치·속도·팔꿈치 각도·가시성으로 128개 특징을 만들었습니다. 미래 프레임을 보지 않습니다. 학습은 구간별 3프레임마다 추출한 576개 표본이며, 긴 구간이 결과를 독점하지 않도록 가중치를 줬습니다.
- Logistic Regression, 작은 MLP(32→16), ExtraTrees 160개 트리를 Lite와 Full 각각 실제 학습했습니다. 가중치와 전체 결과는 로컬에 보존했습니다. 재사용 학습 명령도 추가했고, 독립 실행에서 Lite 평가 결과가 정확히 재현됐습니다.
- 예전 수집 자료는 별도로 점검했습니다. 품질 선별된 4명·156개 트라이얼을 참가자별로 분리해 실제 학습/평가한 결과는 Logistic 106/156, MLP 99/156, ExtraTrees 112/156입니다. 이 자료의 안내 라벨은 완전 검수되지 않았고 전체 3초 구간을 쓰므로 실시간 인식률이나 새 데모 성능으로 해석하지 않습니다. 나머지 미검수/불완전 자료를 무조건 학습에 넣지 않았습니다.

## 연속 동작으로 비교한 결과

자세가 잘 구분되는 프레임의 정확도보다 **실제 공격 누락·추가 발동·복귀**를 우선했습니다. 아래는 실제 수행 공격만의 결과입니다. 학습 분류기 표가 이동·블락 전체 게임 성공률을 뜻하지는 않습니다.

| 방식 | 15:47 실제 공격 11회 | 추가 공격 | 16:17 실제 공격 16회 | 추가 공격 |
|---|---:|---:|---:|---:|
| 기존 v6 + Lite | 11/11 | 0 | 14/16 | 0 |
| 보완 v7 + Lite **기본값** | 11/11 | 0 | 16/16 | 0 |
| Lite Logistic | 11/11 | 0 | 14/16 | 2 |
| Lite MLP | 10/11 | 1 | 16/16 | 0 |
| Lite ExtraTrees | 10/11 | 0 | 15/16 | 0 |
| 보완 v7 + Full | 11/11 | 0 | 16/16 | 0 |
| Full Logistic | 11/11 | 1 | 16/16 | 0 |
| Full MLP | 11/11 | 0 | 16/16 | 8 |
| Full ExtraTrees | 6/11 | 0 | 15/16 | 0 |

검증 세션에서 가장 나은 학습 후보는 Lite Logistic입니다. 순수 자세 구간의 macro-F1은 검증 .990, 세션 평가 .977이지만, 연속 동작에서는 추가 발동이 생겼으므로 이를 ‘게임 인식률 99%’라고 부르지 않습니다. MLP가 마지막 세션에서 맞았다는 이유로 검증 결과를 무시하고 선택하지 않았습니다.

Logistic으로 새로 넓힌 가드 범위만 추가 확인하는 조합도 4세션을 재생했습니다. Lite·Full 모두 공격 결과가 v7과 동일하여, 개선 효과가 없는 추가 계산을 기본 실행에 넣지는 않았습니다. 이 조합은 `--guard-model`로 선택 가능합니다. 모델 단독 판정이 가시성·가드 위치·팔꿈치 각도·시간 조건을 우회할 수 없습니다.

## Lite와 Full 선택

동일한 원본 RGB, 시간 순서, VIDEO 설정, CPU 설정으로 4세션의 Full 관절을 다시 추출했습니다. 영상/관절 대응과 원본 해시를 확인했습니다.

- 300프레임씩 순서를 바꿔 측정한 관절 추론 중앙값: Lite **5.44–5.48ms**, Full **6.65–6.66ms**. 카메라·영상 저장·인식기·화면·통신 시간은 제외한 수치입니다.
- 15:47 이동/정지: Lite **6/6**, Full **5/6**. Full에서 작은 왼쪽 기울임 하나가 누락됐습니다.
- 16:17 이동/정지: 둘 다 실제 시도 **7/7**, 이동/복귀 구간 밖 이동 0프레임.
- Full은 일부 가드를 더 잘 잡았지만 전체적으로 개선되지 않았습니다. 현재 조건에서는 Lite를 유지합니다. 관절 좌표의 별도 정답이 없으므로 ‘Lite의 관절 정확도가 보편적으로 더 높다’는 결론은 아닙니다.

## 누락·복귀 수정

1. 눈높이에서 C 보정한 뒤 턱 높이로 돌아오면 가드 아래 경계를 벗어나던 문제를 보완했습니다. 상대 높이 허용을 .30→.45 어깨너비로 넓히되, 손이 어깨 아래로 내려가는 절대 높이 제한, 구부린 팔꿈치, 낮은 속도, 180ms 복귀 조건은 유지합니다. 기준점은 동작에 따라 이동하지 않습니다.
2. READY는 양팔과 레이즈 채널이 회복되고 **현재 실제 가드 자세**일 때만 표시합니다. 과거에 준비됐다는 이유로 손을 내린 뒤에도 READY가 남던 표시를 바로잡았습니다. NONE은 쉬는 상태이며 가드나 블락이 아닙니다.
3. Space로 다음 동작에 넘어가면 PREPARE에서 양손을 다시 가드로 돌려놓습니다. 최소 2초 및 READY 연속 700ms를 확인한 뒤 GO가 표시됩니다. 키보드에 손을 내린 직후 동작을 시작해 누락되던 흐름을 줄였습니다. 안내 진행은 인식 성공의 정답 라벨이 아닙니다.

최신 16:17 재생: 왼손 레이즈 **3/5→5/5**, 좌우 펀치 **6/6 유지**, 오른손 레이즈 **5/5 유지**, 블락/해제 **3/3**, 이동/정지 **7/7**, GUARD 안내 내 실제 준비 자세 **23/23**, 검토한 휴식 구간의 공격·블락·이동 오발동 없음. 먼저 놓쳤던 왼손 레이즈는 6790·9489 프레임에 발동하고, 복귀 뒤의 재시도도 각각 한 번씩 발동합니다.

이전 14:04·14:39 공격 각 12/12와 동작 후 복귀가 유지됩니다. 두 과거 촬영의 마지막 GUARD는 각각 손이 낮거나 높고 비대칭인 실제 자세여서 준비 완료로 강제 처리하지 않습니다. Full은 과거 왼손 내리기 음성 구간에서 READY 1프레임이 남아 추가 장점으로 보지 않았습니다.

촬영 재생·유지 자세 중복 방지·추적 손실·UDP 재전송·모의 카메라 저장·안내·학습 특징의 인과성·모델 저장/추론 등 **69개 검사 통과, skip 0**. 실제 카메라는 자동으로 실행하지 않았습니다.

## 짧은 새 촬영: 왼손 레이즈 5회

저장소 루트의 VS Code 터미널에서:

```bash
bash scripts/run_seated_demo.command --check
bash scripts/run_left_raise_check.command
```

두 번째 명령은 실행부터 영상을 로컬에 저장합니다. 중앙에 앉아 양팔꿈치·손목이 보이게 하고, 편한 턱 높이의 가드에서 C를 누른 뒤 2초 유지합니다.

1. READY가 표시되면 Space를 누릅니다.
2. PREPARE 동안 손을 가드로 돌려놓고 기다립니다. GO가 보이면 자기 왼손을 올립니다. 서두를 필요 없습니다.
3. Space로 GUARD 안내로 넘어가 중앙·가드로 복귀합니다. READY 확인 후 다시 Space를 누릅니다.
4. 5회 뒤 REST에서 중앙을 유지하고 양손을 편하게 내려 약 10초 쉽니다. Space 후 마지막 가드로 돌아와 READY가 되면 Space로 마칩니다. 중간 종료는 Q입니다.

전체 동작 확인은 기존 `bash scripts/run_six_gesture_check.command --movement`입니다. 이 새 촬영은 아직 수행되지 않았습니다. 먼저 짧은 독립 촬영으로 수정의 재현성을 확인한 뒤 Unity 실제 플레이를 진행합니다.

## 학습 재실행·선택 모델

학습 의존성은 저장소 requirements의 scikit-learn 1.8.0, joblib, NumPy를 사용합니다. `--labels`에는 세션 경로·split·source_hashes·검수 core 구간을 적은 로컬 JSON을 전달합니다. `docs/training-protocol-v7.json`은 이번 학습의 고정 설정입니다. 출력은 기존 폴더를 덮어쓰지 않습니다.

```bash
PYTHONPATH=src .venv/bin/python -m redbool_demo.train \
  --labels /absolute/path/to/labels.json \
  --protocol docs/training-protocol-v7.json \
  --output /absolute/path/to/new-training-output --variants Lite
```

Full 학습은 동일 프레임의 Full 추출 캐시 폴더를 `--pose-cache`로 지정하고 `--variants Lite Full`을 사용합니다. 원본 라벨과 학습 산출물은 개인 로컬 자료이므로 PR에 포함하지 않습니다.

이 Mac에 설치된 선택 실행 예시:

```bash
bash scripts/run_seated_demo.command --check --guard-model local_data/seated_training_20261104/Lite_logistic.npz
bash scripts/run_seated_demo.command --check --pose-variant Full
```

`--check`는 카메라·UDP를 열지 않으며 모델/관절 종류 불일치도 검사합니다. 실제 실행에는 `--check`를 빼고 필요한 `--movement`, `--host`를 지정합니다. 기본 실행은 선택 모델 없이 Lite + v7입니다. 다른 PC에는 Full 관절 자산과 선택 학습 모델이 자동 배포되지 않습니다.

검사 실행은 `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test_*.py'`입니다. 촬영 회귀 검사는 기존 네 세션 환경변수에 `REDBOOL_CHIN_SESSION`(16:17 촬영)을 추가해야 합니다. 제공하지 않으면 해당 검사는 skip되며 촬영 인식률 검증을 뜻하지 않습니다.
