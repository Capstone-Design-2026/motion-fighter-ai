X자 보조 관절 추정과 블락 복귀 수정 — 2026-11-16

결론
블락 복귀를 막던 원인을 수정하고 검증된 소스에 반영했다. 보조 Heavy 모델은 명시적으로 선택하는 기능으로 넣었으며 기본 Lite/Full 인식은 유지했다. 기존 앱/EXE/ZIP은 이번에 다시 만들거나 바꾸지 않았다. 추가 촬영·물리 카메라 실행·원본 수정·Git push는 하지 않았다.

원인과 수정
기존 보조 추정 후보는 ‘같은 X를 두 번 발사하지 않기 위한 잠금’과 ‘블락·일반 공격 금지’를 하나로 묶었다. 실제 two_person_latest 기록에서 원래 일반 입력이 복귀할 203.553초가 209.654초까지 약6.101초 밀렸고, 정상 높은 블락8프레임이 사라졌다.
수정 후 일반 블락·공격은 원래 세 모델의 팔 분리 기준과180ms 복귀 시간을 따른다. X 재발사 보호는 별도로 유지한다. 보조 결과가 없거나 늦어도 일반 동작을 추가로 막지 않는다. 실제 같은 프레임의 X 증거가 다시 보이면 일반 공격을 억제한다. 손목 소실·지난 프레임·다른 사람 좌표를 팔 분리 증거로 사용하지 않는다. 보조 모델이 없어도 같은 X를 기본 모델이 다시 보았다는 이유만으로 재발사할 수 없다.

기존 기록 비교
1. 보조 모델을 사용하지 않는 경로: 원시9세션90,575프레임/550이벤트, 기존 journal37세션146,076프레임/407이벤트, 278의3세션6,270프레임/10이벤트, 개인 보정 스트레스13,806프레임/98이벤트를 비교했다. 합계256,727회 프레임 평가이며 스트레스는 같은 세션의 별도 재생이다. 전체 이벤트 필드·블락·이동·보정·개인 프로필이 현재 선택 기준과 같다. 기록 시각으로 계산한 판정 시점도 동일하다. 이는 새 하드웨어 실측 지연0이라는 뜻이 아니다.
2. 보조 관절 재추정 경로:9세션90,575프레임에서550→558이벤트. 기존 펀치·레이즈 이벤트는 그대로이고 블락·이동·추적·보정 출력의 차이가0이다. 이전에 없어졌던 블락8프레임은 원래 시점에 복구됐다. 기존 SPECIAL2개만 약101/164ms 앞당겨졌다.
3. 새 SPECIAL8개는 실제 RGB에서 X를 유지한 구간인지와 사이에 팔을 풀었는지 확인했다. 목표인353/358초 시도2개와 다른 미검출 X6개다. 사후 영상 확인이므로 일반 인식률·새 사람 정확도 수치로 쓰지 않는다. 일반 공격 추가, 같은 유지 자세의 중복 필살기는 확인한 비교에서0이다.

실제 시간·모델로 재생한 확인
원본 영상350~362초를30Hz 최신 프레임 방식으로 공급했다. 보정·엔진의 앞선 상태는 기존 관측으로 복원하고, 현재 처리 시계와 실제 Lite VIDEO/Full VIDEO/Full IMAGE/Heavy IMAGE를 사용했다. Heavy는 정상 건강도30관측과 실제 X 대기 상태를 거쳐 사용했으며 강제 활성화하지 않았다.
- 첫 A/B: 기본0회 → 보조2회 X(355.402/359.901초). 두 경로360/360프레임 처리. 전체 처리 age p95 약19.36→28.29ms.
- 둘째 A/B: 기본0회 → 보조2회 X(355.869/359.703초). 기본360/360, 보조359/360 처리. age p95 약23.53→27.08ms.
- 약30fps, 두 쌍 모두120ms 초과 관측0·100ms 초과 처리 관측 간격0·일반 공격 추가0. 보조 총311요청 중290수용, 나머지는 사용하지 않았다. worker는 모두 종료됐다.
- 네 발사 프레임 모두 실제 X 유지 중임을 영상으로 재확인했다. 그러나 발동은 여전히 늦다. ‘첫 X를1초 유지하면 항상 즉시 성공’이 해결됐다는 뜻이 아니다.
- 결과 대기 설정은10ms지만 OS 스케줄링을 포함한 실제 대기 최대12.55ms가 있었다. 10ms 절대 보장이라고 표현하지 않는다.
- 이 시험은 Mac의 저장 영상12초 구간이다. Unity 렌더·네트워크·웹캠 미리보기·진단 기록 부하와 저사양 Windows는 포함하지 않았다.

남은 부분과 적용 범위
139.8초 시도는 앞선 X 뒤 손이 화면 밖으로 나가 실제 팔 분리 증거가132.5ms로 부족했다. 이를 임의로 재무장시키면 유지 중 중복 필살기 위험이 있어 그대로 보호한다.
Heavy는 기본 OFF다. 명시적으로 선택해도 처리 여유가 있는 경우에만 같은 프레임을 보조한다. 과부하·반복된 늦은 결과는 보조 기능만 중지한다. 모델 파일이 우연히 있다는 이유로 자동 사용하지 않는다. 기존 잘 되던 기본 인식과 스토리·PvP의 게임 코드/전송 규칙은 바꾸지 않았다.
블락 복귀 수정과 선택형 보조 추정 소스는 반영 완료. 기본 활성화·Mac/Windows 배포는 별도 패키지의 검증 후 판단해야 한다. 이번 결과만으로 모든 PC의 무지연·오발동0·게임 품질을 보장하지 않는다.
