REDBOOL 통합 시험판 · 2026-11-17

이 분기는 스토리·LAN·온라인에서 같은 인식 코드를 사용하는 시험판이다.
v36.3 안정판 배포 파일은 롤백용으로 보관한다. 아직 실물 검증을 마친 안정판으로 승격하지 않는다.

변경
- 동일한 불변 관절 표본의 특징·유효성 계산을 공유한다. 각 동작 채널의 상태·보정·출력은 독립적으로 유지한다.
- 실제 가드에서 출발하고 연속 세 표본의 팔꿈치 펴짐·앞쪽 이동·상완 투영 단축이 일치할 때만 정면 펀치 후보를 추가한다. 원래 확정·물리 복귀 조건은 유지한다.
- 레이즈 확대 후보는 기존 높은 펀치를 레이즈로 오인해 제외했다.
- 가상 카메라 검사는 실제 보정과 선택형 보조 모델 준비 후 X자를 시작한다. 촬영 픽셀에 자세 코드를 고정하므로 서로 다른 비동기 모델도 같은 프레임을 해석한다. 이벤트 양수·정확 재생·원래 유효시간 검사 기대값은 그대로다.

재현과 검증 범위
- 기존 60세션·328,134프레임에서 이전 공격 1,416개를 보존하고 정답 영상이 없는 오른손 펀치 1개가 추가됐다. 이를 일반적인 인식률 향상 수치로 해석하지 않는다.
- 기존 수동 확인 조건은 139개 중136개로 동일하다. 기존 X 누락3개는 남아 있다.
- 중복 계산 최적화는 개발 Mac 규칙 엔진 CPU만 약65% 줄였다. 모델 추론·게임 프레임·Neo 실물 성능의 동일 비율 개선을 의미하지 않는다.
- 이전 전체 검사에서 이벤트0으로 실패한 선택형 보조 모델 검사는, C 직후 처리650ms 지연을 넣으면 수정 전·후 모두 재현됐다. 고정된 캡처60~109번에서 보정 중 X가 지나가던 시나리오였다. 준비 완료 후 시작하는 검사로 같은 지연에서 원본·현재판 모두 X1회와 정확재생을 확인했다. 최초 전체 검사 때 발생한 OS 지연 자체까지 소급 확정한 것은 아니다.
- 시험판 전체 검사와 각 운영체제의 네이티브 빌드 검사는 별도 결과로 판단한다. 기본 카메라를 켜지 않는 가상 이미지·연결 검사만 자동 실행한다.

배포
Windows 카메라는 camera-backend-windows.yml의 Windows x64/Python3.11 작업으로 만든다.
source baseline·모델 바이트·인식/보정/전송/진단·Windows 파일 공유·동일 프레임 보조 모델 검사를 거친 뒤 네이티브 실행 파일을 생성한다.
산출물의 source_commit, source_sha256, source_dirty=false를 실제 실행 응답·내장 출처·옆의 빌드 명세에서 모두 비교한다. 다른 버전 실행 파일에 출처 정보만 덮어쓰지 않는다.
Mac 카메라는 Apple Silicon용으로 별도 네이티브 빌드하고, 포함된 모든 네이티브 파일의 최소 macOS 버전을 검사한다. Intel Mac을 지원한다고 표시하지 않는다.
완성된 배포 ZIP을 받은 테스터는 Python·Unity·Git을 설치하거나 빌드할 필요가 없다.
