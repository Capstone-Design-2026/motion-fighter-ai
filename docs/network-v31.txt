REDBOOL v31 — 두 노트북 끊김 수정과 촬영 없는 통신 검사
기준: 2026-11-12. v26 동작 판정과 개인 보정 유지. 화면 프로토콜은 29 그대로.

이번 v30 기록에서 확인한 원인
1. 양쪽 수련은 완료됐다. 전투가 시작된 뒤 74.38초 중 게임 시간은 36.93초만 흘렀고 재개 로그가 시작 포함 81번 생겼다.
2. Windows 명령 왕복 응답 p95가 이전32ms에서172ms로 늘었다. 호스트 수신 후 게임 처리 대기는 p95 약16ms로 그대로였다. 네트워크 또는 Windows 송수신 스케줄링 경로가 악화됐다. 공유기 간섭인지 절전/부하인지는 기존 로그로 확정할 수 없다.
3. Windows 전체 처리속도는28.55→20.95fps. 수련 원본의 카메라 공급 자체가 첫10초 뒤 약20fps로 내려갔다. 모델만 줄이면 해결된다고 볼 근거는 없다.
4. 짧은 입력 만료를 매번 전투 전체 정지와 공격 취소로 처리했고, 시계 동기화 표본이 없으면 STATE 전송까지 수초 멈출 수 있었다.
5. 두 화면에서 조립한 상태342개 표본은 모두 동일했다. 전투 중 반복 끊김을 설명할 렌더링 FPS 붕괴는 관찰되지 않았다.

수정
- 불안정한 시계 동기화는 최대5Hz로 재시도하고 최근의 정확한 표본을 선택한다. 원래3초 표본 수명과25ms 불확실성 상한을 연장하지 않는다.
- Windows Python3.11에서 캡처·인식·통신 모두 동일한 고정밀 시계를 사용한다. 기존 기록 재생 시각은 바꾸지 않는다.
- 150ms 입력 수명은 유지한다. 만료되면 해당 사람의 이동·블락은 해제하고 새 공격은 거절한다. 전투 연결 상태만 원래 입력 마감 뒤100ms까지 유지해 이미 시작한 공격이 순간적인 통신 지연으로 취소되지 않게 한다.
- 실제 추적 손실, 보정 해제, 카메라 종료는 유예하지 않는다. 장기 단절은 양쪽 전투를 멈추고 오래된 공격을 폐기한다. 재개 순간은 양쪽의 신선한 입력이 필요하다.
- 카메라 공급속도·읽기 시간·설정과 동기화 복구를 작은 진단 ZIP에 포함한다. 노출/밝기/모델을 임의로 변경하지 않는다.
- --recording logs에서 영상 객체가 없을 때 발생하던 오류를 고쳤다.

권장 연결
- 같은 공유기/스위치에 유선 LAN으로 두 노트북을 연결하는 구성을 우선 권장한다. 인터넷 서버는 필요 없다. 한 노트북이 판정 호스트다.
- 유선이 없으면 두 노트북을 가까운 동일 공유기의5GHz Wi-Fi에 연결해 아래 검사로 비교한다.
- 휴대폰 핫스팟은 대안으로 비교 가능하나 항상 빠르지는 않다. 기기 사이 통신 허용 여부, 지원 대역, 전파 상태에 따라 다르다. 변경하면 호스트 IPv4도 다시 확인한다.
- 외부 서버는 같은 무선 구간과 느린 카메라 공급을 해결하지 못하며 인터넷 왕복 경로가 추가된다. 현재 시연에서는 우선 도입하지 않는다.
- Windows는 전원을 연결하고, 밝은 실내에서 다른 카메라 앱을 닫은 상태를 권장한다. 카메라20fps 원인을 이것으로 확정한 것은 아니다.

촬영 없는20초 검사 (카메라는 켜지 않아도 됨)
1. Mac Unity 저장소에서:
  python3 Tools/Developer/run_game.py host
2. Windows Unity 저장소에서 호스트 주소를 확인해:
  py -3.11 Tools\Developer\run_game.py join --host <Mac의현재IPv4>
3. Windows Python 저장소에서:
  .\.venv\Scripts\python.exe scripts\check_pvp_network.py --host <Mac의현재IPv4>
꺾쇠 부분은 실제 주소로 바꾼다. 예: --host 172.30.1.83
결과는 Python 저장소 local_data/network_checks/날짜_시간.json에 저장된다.
이 검사는 플레이어를 연결하거나 수련을 초기화하거나 공격을 보내지 않는다.
RTT는 네트워크 왕복+호스트 게임 업데이트 대기이며 동작 인식 지연과는 다르다.
유선/Wi-Fi/핫스팟에서 같은 방식으로 비교한다. 손실0%에 가깝고 p95가 낮으며 긴 최대지연이 없는 연결을 선택한다.
0응답이면 v31 호스트가 실행 중인지, 현재IP와UDP5067 방화벽을 확인한다.
특정 RTT 하나만으로 완벽한 게임 성능을 보증하지 않는다. 실제 시연망에서 확인해야 한다.

통신이 안정된 뒤 기존 카메라 실행 (게임은 위에서 켠 상태)

Windows Python 저장소:

종료는 각 카메라Q, 저장 완료 후 게임 종료.
