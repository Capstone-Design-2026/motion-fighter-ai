# REDBOOL 앉은 자세 데모 v6 — 2026-11-04

Python 인식과 로컬 실행은 v6로 갱신했습니다. Unity 연결 규약과 동작 매핑은 기존 v5 수신기와 호환됩니다.
이 버전은 관절 기반 규칙을 개선한 것이며 분류 모델을 새로 학습한 버전이 아닙니다.

## 바로 실행

저장소 루트에서 기존 Python 3.11 `.venv`, requirements, MediaPipe Lite `pose_landmarker.task`를 사용합니다.

```bash
bash scripts/run_seated_demo.command --check
bash scripts/run_six_gesture_check.command --movement
```

첫 명령은 카메라와 UDP를 열지 않습니다. 두 번째 명령은 시작부터 영상·관절·로그를 로컬에 저장합니다.
카메라 창을 선택하고 영문 입력 상태에서 진행합니다.

1. 중앙에 앉아 편한 가드를 잡고 C를 누른 뒤 2초 유지합니다.
2. 첫 GUARD 안내에서 준비되면 Space를 누릅니다.
3. 다음 안내를 천천히 읽고 해당 동작을 한 번 합니다. 급하게 반응할 필요가 없습니다.
4. 동작을 마쳤으면 Space로 GUARD 안내로 넘어가 중앙과 편한 가드로 돌아옵니다. 준비 후 다시 Space를 누릅니다.
5. NONE/REST에서는 중앙에서 손을 편하게 내려 10초 정도 쉰 뒤 Space를 누릅니다. 마지막 GUARD에서는 다시 가드로 돌아온 뒤 Space로 마칩니다.
6. 중간 종료는 Q입니다. 전체 안전 종료 시간은 30분입니다. Space는 짧게 한 번씩 누릅니다.

SPACE는 안내 완료 표시일 뿐 인식 성공 판정이 아닙니다. 동작 안내와 인식 결과를 따로 저장하므로 누락이 있어도 다음 단계로 갈 수 있습니다.
각 단계 직후 1초 이내의 Space는 실수 방지를 위해 무시합니다. 기존 자동 안내는 `--guided-timed --seconds 240`으로 선택할 수 있습니다.
M은 이동 켜기/끄기, X는 일시정지입니다. 검사 중 C로 재보정하면 검사는 중단되므로 Q 후 다시 시작합니다.
좌우는 화면이 아닌 자신의 왼손/오른손입니다. 이동은 의자를 고정한 상태에서 상체를 옆으로 기울입니다.

## 변경

- 기존 어깨 중심 이동(.22 어깨너비)에 더해, 작은 중심 이동(.14)과 같은 방향 어깨 기울기(3도)가 함께 120ms 유지되면 이동합니다. 중앙 복귀에는 별도 낮은 기준을 사용합니다.
- 한쪽 어깨만 올리기, 작은 흔들림, 반대 방향 기울기, 짧은 잡음은 새 이동을 만들지 않습니다. 화면 비율과 좌우 반전을 처리합니다.
- 인식된 작은 기울임도 실제로 움직일 수 있도록 최소 입력 세기를 .35로 설정합니다. Unity는 기존 60ms 평활화를 적용합니다. 최종 체감 속도는 실제 게임에서 확인해야 합니다.
- 가드 아래쪽 허용 범위를 보정 위치 대비 .20→.30 어깨너비로 보완했습니다. 팔꿈치의 2D/3D 각도, 손 위치·속도와 복귀 유지 시간은 함께 검사합니다. 팔을 뻗거나 손을 내려 놓는 상태를 READY로 강제 전환하지 않습니다.
- 촬영 안내를 사용자가 Space로 넘기는 방식으로 바꿨습니다. 안내 문구가 화면을 넘지 않도록 표시 크기도 맞춥니다.
- 어깨 추적 손실과 오래된 입력에서는 이동을 해제하고, 공격 이벤트는 중복·만료 검사를 유지합니다.

두 PR의 대상 브랜치는 각각 feature/vision-v2, feature/unity입니다. 한 PR만 합치면 다른 브랜치의 코드까지 자동 적용되지는 않습니다.
검토 중 Python PC는 `codex/seated-vision-demo-v5-20261104`(이름은 그대로이며 내용은 v6), Unity PC는 `codex/unity-vision-demo-v5-20261104`를 사용합니다.
기존 변경이 있는 폴더에서 무리하게 checkout하지 않습니다. 이 Mac에는 검증한 v6 파일을 직접 반영했습니다.
ZIP 복사는 필요 없습니다. Unity 팀원은 PR #4의 `Docs/RedboolVisionSetup.md`에 따라 씬에 수신기를 추가하고 저장합니다.

같은 LAN에서 Unity가 Play 상태일 때 아래 예시 IP를 실제 Unity PC 주소로 바꿔 실행합니다.

```bash
bash scripts/check_unity_connection.command --host 192.168.0.10
bash scripts/run_seated_demo.command --host 192.168.0.10 --movement --seconds 600
```

첫 명령은 카메라 없이 실제 게임에 입력을 보내므로 안정된 전투 상태에서 실행합니다. 127.0.0.1은 Unity도 같은 PC에서 실행할 때만 사용합니다.
게임 중 GAME_BUSY는 공격/방어/피격 후딜로 거절한 입력이며 인식 실패와 구분합니다. 거절한 공격을 뒤늦게 재생하지 않습니다.
블락은 게임의 기본 1.5초 시간제 방어이며 손을 내린다고 이미 시작된 게임 방어를 즉시 취소하지 않습니다.

## 남은 실행 확인

현재 Mac에 Unity Editor가 없으므로 Unity 컴파일·Play Mode·실제 화면 지연은 확인하지 못했습니다.
PR은 검토용 상태이며 병합하지 않았습니다. 다음은 독립 촬영 1회와 팀원 PC의 실제 플레이 확인입니다.

1. 새 안내로 동작 3회씩 검사하고 NONE에서 쉬었다가 가드 복귀를 확인합니다.
2. Unity Console 오류 없음 → Input Adapter Self Check → 연결 검사 passed를 확인합니다.
3. 네 공격, 시간제 방어, 좌우 이동/정지, 카메라 회전 후 방향, 연결 종료 후 이동 정지를 화면으로 확인합니다.
4. 2~3분 연속 플레이에서 GAME_BUSY, 중복 입력, 과도한 이동 속도와 체감 지연을 확인합니다.

추가 학습은 오늘 데모의 필수 선행 작업이 아닙니다. 다양한 참가자·거리·조명에 대한 일반화가 필요하면 실제 구간을 검토한 라벨과 참가자/세션 분리 평가를 먼저 준비합니다.
