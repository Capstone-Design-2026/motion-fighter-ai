# 높은 블락 이후 낮은 오른손 펀치 점검 — 2026-11-10

원본 실행: 20261110_022511_4d0f5e3a, 세션 824d046b10434d63b90d9ba77d64cae4. 영상 시간 136.98초, 실제 인식 엔진 v19. 영상/원본 로그는 변경하지 않았다.

## 실제 실행 결과와 수정 전후

- 실제 v19는 RIGHT_PUNCH 28회. Unity가 24회를 STRAIGHT로 적용했고 4회(56.073, 69.340, 76.041, 111.311초)는 피격 경직으로 거부했다. 네 건 모두 블락이나 가드 복귀 지연이 아니었다.
- v20 동일 영상·동일 시계 재생은 RIGHT_PUNCH 31회. 54.471, 57.772, 123.110초에 실제 낮은 오른손 펀치 3회를 추가 검출했다. 기존 28회는 모두 유지되며 56.073초 입력만 56.037초로 약 36ms 앞당겨졌다. 다른 손 펀치·레이즈·필살기 추가 입력 없음.
- 새로 검출된 세 펀치는 모두 왼손을 이마 부근의 높은 블락에 유지한 채 오른손을 낮게 뻗는 동작이었다. 기존 반대 손 가드 조건이 너무 낮고 좁아 누락됐다.
- 수정은 반대 손이 높더라도 팔꿈치가 접혀 있고, 위치가 몸 가까우며, 움직임이 느린 경우만 펀치 판정의 보조 가드로 인정한다. 공격 팔의 펴짐·가로 이동 조건과 물리적 복귀 조건은 유지한다. 보조 가드 판정은 READY 상태나 보정 기준을 바꾸지 않는다.

## 요청 항목별 확인

1. 첫 기본 펀치 3회: 15.232, 17.598, 20.168초에 각각 1회 인식 및 게임 적용. 처음 펀치는 영상상 약 14.9초부터 손이 움직이고 15.232초에 입력이 나간다. 팔 유지 후 수초 뒤 발생하는 현상은 없다. 입력 근거 프레임 촬영부터 게임 응답 수신까지 각각 43.82, 46.54, 41.86ms. 이는 전체 동작 시작~화면 연출 지연 측정값은 아니다.
2. 블락 해제: 실제 공격으로 이어지는 5개 해제 구간에서 첫 응답은 guard=false 및 can_act=true. 약 28~44ms에 해제 확인. 종료 직전 짧은 블락의 해제도 guard=false이나 직전 공격이 진행 중이라 can_act=false였다. 유지 중인 블락을 강제로 끊거나 공격을 나중에 몰아 실행하는 처리는 추가하지 않았다.
3. 짧은 오른손 펀치: 67.8~77.7초에 확인되는 연속 7회 모두 인식. 2회는 피격 경직으로 게임 적용이 거부됐다. 짧다는 이유만으로 전부 누락되는 상태는 아니다.
4. 팔 유지·좌우 움직임: 88.3~94.4초, 96.6~102.5초 각각 최초 펀치 1회만 검출. 유지 중 중복 펀치·레이즈 없음.
5. 휴식: 60~64.5초의 짧은 휴식 및 134.3초~종료 조작 중 공격 없음. 마지막 10초에는 블락과 실제 펀치가 포함되어 있어 연속 10초 휴식 테스트 완료로 보지 않는다.
6. 성능: 카메라 29.97fps, 촬영~인식 처리 지연 중앙값 13.50ms / 95백분위 18.96ms. Unity 로딩과 종료 구간 제외 59.03~59.70fps, 최대 단일 프레임 44.83ms. Lite/30fps 설정 유지.

## 아직 남은 부분

29.8~30.6, 33.0~33.6, 49.6~50.4, 51.1~51.7, 65.5~66.3초 구간의 낮은 펀치는 여전히 누락됐다. 각각 8/24, 8/18, 14/24, 12/18, 12/24프레임에서 오른손목 또는 팔꿈치가 화면 밖으로 판정됐다. 영상에서도 낮게 뻗은 손이 하단 가장자리로 나간다. 이 좌표를 무조건 유효 처리하면 화면 밖 추정치로 오발동할 수 있어 유효성 조건은 유지했다.

다음 실행에서는 조금 뒤로 앉거나 카메라 각도를 조정해 양팔꿈치와 낮게 뻗은 주먹 전체가 화면 안에 들어오도록 맞춘 뒤 C로 보정한다. 프레임을 높이거나 모델을 재학습해도 화면 밖 동작의 관측 공백 자체는 채워지지 않는다. v20의 실제 라이브 확인은 아직 남아 있다. 저장 영상 재생 31회는 실제 게임 성공 31회나 독립적인 인식 정확도를 뜻하지 않는다.
