X자 관절 추정·저속 입력 후속 검토 — 2026-11-16

검증을 통과한 저속 X자 확인·해제와 미리보기 부담 감소만 로컬 소스에 적용했다.
Heavy 보조 관절 추정과 Full 확대 추정은 연구 폴더에 보존하고 생산 코드에는 넣지 않았다.
기존 v36.2 앱·Windows EXE는 이번 작업에서 다시 만들거나 교체하지 않았다. GitHub push도 하지 않았다.

278 진단
- 기록의 실제 실행 버전은 v36.1이다. 같은 입력을 v36.2에도 재생해 같은 X 누락을 확인했다.
- 카메라 획득은 약30fps지만 인식 처리는 약10~12fps였다. 최근 실행은 X자 수련에 들어간 뒤
  약84초 동안 SPECIAL이0회여서 전투로 넘어가지 못했다. 이전 펀치·레이즈 이벤트9개는 남아 있다.
- X자로 보이는 관절이 지속된 구간에서도100ms보다 긴 처리 프레임 간격과120ms를 넘긴 입력으로
  연속700ms 확인이 반복 초기화됐다. 단순히 테스터가 동작을 너무 빨리 끝낸 문제로 판단하지 않았다.

적용한 수정
- Full 보조 모델을 실제 사용하지 않으며 최근20개 입력 간격 중8개 이상이100ms를 넘는 구간에만
  별도의 정지 X 확인을 허용한다. 현재 프레임이120ms 이내이고 양팔 관절이 모두 유효해야 한다.
- 원래의 엄격한 X 모양을 유지하고 몸·팔이 안정된8표본 이상에서700ms를 확인한다.
  표본 간격은150ms 이내, 한 쌍의 누적 시간은100ms까지만 인정한다. 누락·다른 자세는 증거를 끊는다.
- 이 경로로 발사한 X에 한해서, 현재 유효한 양손이 각각 바깥으로 떨어진3표본·180ms 확인으로
  잠금을 해제한다. 일반 X·펀치·레이즈·블락의 판정 기준은 그대로다. 추적 손실로 해제하지 않는다.
-270ms는 이 정지 자세의 사적 증거를 폐기하는 한계다. 기존 일반 입력 간격100ms,
  관측 신선도120ms, 출력·공격 만료150ms, 일반 인식 연속성220ms를 늘린 것이 아니다.
- 기존 과부하 판정이 켜지면 웹캠 미리보기 생성 상한을8fps로 낮춘다. Unity가 이미8fps로
  소비하던 구간에서 불필요한 JPEG 작업을 줄인다. 일반 환경의 기존 상한과 인식 입력은 유지한다.

수정 전후
- 기존9개 영상 기록90,575프레임과37개 진단 기록146,076프레임의957개 이벤트가 모두 동일했다.
  추가 오발동, 기존 이벤트 누락·시각 변경, 블락·이동·추적·보정·개인 프로필 변화가 없었다.
  별도 개인 보정 최소속도 검사13,806프레임도 동일했다. 이를 새로운 사람의 전체 정확도로 해석하지 않는다.
- 원래139개 평가 조건은136/139로 동일했다. 기존 X자 누락3개는 선택한 기본 인식에서 아직 남는다.
- 새278의6,270프레임에서는 기존9개 이벤트를 보존하면서 X0→1회가 됐다.2483프레임에 확인하고
  2539~2541의 현재 양손 분리 증거로 해제됐다. 새 X 상태 외 블락·이동·추적 손실은 없었다.
-278에는 원본 영상이 없다. 이번1회를 사람의 의도를 독립적으로 확인한 정확도 개선이나
  수련2회 성공으로 주장하지 않는다. 뒤의 새 X에 충분한 신선한700ms 증거가 없어 두 번째는 추가되지 않았다.
- 선택 소스 관련 집중 검사79개 통과. 내부 통신15개와 기존 좌표를 넣은 가짜 카메라3개도 통과했다.
  검사 묶음 간 중복이 있으므로 합산한 숫자를 별도 정확도 지표로 사용하지 않는다. 실제 카메라는 열지 않았다.

관절 추정 후보를 보류한 이유
- Full 모델에 몸통 확대 영상을 넣는 후보는 목표 누락을 복구하지 못했다.
- Heavy 모델은 기존3회 누락 중2회를 좌표 실험에서 복구했다. 넓은 비교의 추가 X8개도
  원본 영상에서 실제 별도 동작으로 확인했다. 원래 평가 창은 바꾸지 않았다.
- 그러나 X 후 실제 블락이8프레임 늦어졌고, Heavy 결과가 사라지는 별도 반례에서는
  정상 블락이3초 동안 막혔다. X 유지 중 중복 발동을 막는 보호와 복귀 추정이 충돌했다.
  기존에 잘 되던 동작을 유지한다는 기준을 충족하지 못하므로 기본·선택 실행 모두 생산에 넣지 않았다.
- Mac 저장 영상30Hz 실제 계산 비교는960프레임 누락0·120ms 초과0이었지만 처리 지연p95는
  약18→26~28ms로 늘었다. 이는 Unity 동시 실행이나 저사양Windows 성능 보장이 아니다.

원본 영상·진단ZIP·기존 Lite/Full 모델을 보존했다. 통신·Unity·스토리·PvP 코드는 변경하지 않았다.
추가 촬영 없이 검증했으며, 다음 관절 추정 채택 조건은 누락 복구와 함께 정상 블락·후속 공격·반복 방지를
동시에 통과하는 것이다. 이전 앱에는 자동 반영되지 않으므로 실제 배포 전 새 빌드가 필요하다.
